Collective usage intake

Receive one supplied report across declared customers, reconcile every expected population and control total, then hand its exact partitions to native pricing. This is Finance intake, not provider authentication or a new approval/signature gate.

What to supply

Add typed usage_intake_source and usage_intake_controls JSON evidence on this case. Include the explicit case/provider namespace and reference, report and source version, year/month, extraction and cut-off timestamps, completeness, customer/service/contract/unit rows, expected existing coverage IDs, currency, quantities, row counts and supplied control version/approval reference. Missing or unknown values hold the entire collective. Zero usage needs an explicit zero row.

One real delivery has one delivery reference and one operation key. Reuse both after a lost response. A genuinely separate identical resend needs new keys and records a duplicate receipt, not another usage batch. Changed source or controls require a new source version and the exact predecessor. Never route this report to another case.

Source corrections or withdrawal retain earlier partitions, preparations, reviews and issued receipts. New dependent actions need current reconciled evidence. An already issued obligation stays on the separate authorized invoice-correction route.
