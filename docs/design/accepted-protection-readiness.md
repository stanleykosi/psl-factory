# Native readiness for accepted protection operator jobs

Engineering design implemented26–27 October2026 and verified as a bounded capability; actual results are in the build records. BUILD-TESTS.md contains actual results. No business or operational acceptance is asserted here.

The shared operator now has a separate AF13 protection packet selection. Existing PrivateFileReadiness and PrivateProtectionReadiness adapter selectors intentionally require Finance private-readiness packet plans. Their historical `packets` snapshots and SQL provenance must retain that meaning. A job carrying only `private_protection_packet_ids` must continue failing enrollment through those old selectors and cannot enter a public receipt contract.

Inspect an explicit typed native binding for this inventory, with an immutable discriminator and exact selected AF13 packet/accepted-row hashes, job kind, plan/intent/manifest hashes, storage/database identity, health observation and actual receipt provenance. Do not infer a type from overlapping integer IDs. Reuse durable probe workers and human transport review, while preserving code-owned targets, original source grants, owner acceptance, receipt-first recovery and attempt budgets. Keep its criteria independent from the source transport/owner policies to avoid invalidating the evidence it carries. Prohibit recursive evidence self-enrollment rather than generating an endless acceptance chain.

Build capture before configuration, typed inventory/principal/freshness/receipt validators and lifecycle UI, source-filtered choices, bounded live investigation/preparation, exact-effect dispatch enrollment, immutable SQL lineage/history locks and actual SQL/file/isolated recovery tests. Test old contracts unchanged, wrong inventory type, source/owner withdrawal, stale criteria, physical missing/corrupt bytes despite caches, duplicate probes/workers and receipt recovery in a fresh process after revocation. Use only owned synthetic temporary storage and the isolated test drill database. Preserve historical bytes and authority history.

Real target authentication, provider evaluation, process-owner/SOP evidence, least privilege/SSO/TLS, full application/database restore, load/security/UAT and actual operational deployment remain separately tracked requirements. This proposed follow-through must not be represented as those outcomes.

The implementation uses a separate AcceptedProtectionReadiness model and `native_accepted_protection` probe/observation discriminator. Its source schema pins job kind, plan/intent/manifest hashes, reserved storage/target identities and separate `protection_inventory` and `finance_inventory` rows containing packet and accepted-metadata hashes. `INT.accepted_protection_readiness` v1 supplies independent criteria. Existing file/restore source adapters and the AF13 acceptance-source adapter retain their previous meanings; the new evidence cannot recursively become an owner packet. Shared durable workers, human review, configuration lifecycle and per-command evaluation are reused.
