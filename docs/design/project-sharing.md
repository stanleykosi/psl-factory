# P05 shared project projection — proposed next increment

This began as an engineering proposal, not source policy. The bounded implementation is now verified by RUN325/326; see docs/runbooks/project-view.md. Its four supported metadata groups omit case title, issue/change details and other broader suggestions below. Those suggestions remain proposed, not tested behavior.

The source contract calls for a permissioned shared project view across PMO, management and Engineering. General case read currently reveals public case evidence; it is too broad for a recipient entitled only to selected project metadata. Existing document audience rules protect documents and do not define a project overview. P05 does not add an approval of the project view.

Build an explicit, typed versioned D11 shared-project-view interface with named disclosure principal, audience keys, current recipient IDs, permitted metadata groups, source-age thresholds, missing/stale behavior and bounded row budgets. No actual recipients, thresholds or default audience are installed. A missing configuration holds only this projection. Keep the ordinary project workbenches usable.

Recipients need a separate exact-case project-view action grant plus membership in the current chosen audience; do not require or imply broad case-read access. A current named disclosure principal must retain exact-case sharing authority and each selected source-domain read grant. Configuration text alone cannot confer that authority. Reevaluate both sides on every request; preserve configuration history. Do not silently union audiences or fall back to a larger projection.

Initial finite metadata groups should include explicitly selected case title, recorded identifier history, recorded milestone facts, current action status/recorded deadline and delivery event kinds/timestamps. Exclude evidence bodies, notes, meeting decisions, financial/staff records, external source references, names/contact details and private documents. Mark recorded delivery facts as historical observations, never current gate approval or inferred phase. Source-specific freshness uses source timestamps rather than the time the overview was rendered. Unknown/missing sources remain unknown. Row limits must report truncation within the authorized group without revealing hidden records.

Provide server-rendered audience view/configuration screens, safe discovery for recipients without broad case access, an internal projection adapter and bounded deterministic interpretation agent using the identical authorized DTO. The agent cannot retrieve source bodies, widen the audience, grant access or execute effects. No review/publication job is necessary merely to read this live projection.

PostgreSQL acceptance must cover actual source records, current audience/source-principal/recipient grant and active-user changes, policy successors, missing/stale sources, bounded metadata, cross-case/tenant denial, escaping/cache behavior, agent/tool boundaries and recipients without case-read access. General case/document endpoints must continue denying those recipients. Actual owner audience/freshness/disclosure agreement remains a later operational input.
