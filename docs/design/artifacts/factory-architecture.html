1 · Layers

Who can change what

Six parts, and the arrows between them are the architecture. People decide. The factory coordinates. Agents read and draft. Department services make things binding. Outside systems are only reached through adapters, and everything is written to an append-only history.

2 · Objects

The things the product keeps

These are the nouns your screens are made of. The diagram follows one work item through them; the cards say what each one is and where it shows up. Code names are there for conversations with your backend dev.

Workspace

One client project, or a BaaS support case. Every work item, record and document belongs to exactly one.

Shown on Project journey, Start workcore.Case

Work item

One run of one line, such as the invoice for milestone 2. Holds the state, a revision number and an agent effort budget.

Shown on Work queue, Work itemFactoryWork

Step and attempt

A planned step from the 15 step types, plus every try at it. Each attempt links to the agent run that did the work.

Shown on Work item, Agent workFactoryActivity · FactoryAttempt

Agent run

One scoped execution by a specialist agent. It returns a cited result and a suggested next step, never a decision.

Shown on Agent workagents.AgentRun

Evidence

Any source: an uploaded file, an extracted fact, a signed reference. Versioned and fingerprinted. A new version never overwrites the old one.

Shown on Agent work, Import, Reportscore.Evidence

Human task

A request for a person to review, approve or supply information. It names the role needed, and one person claims it.

Shown on Work queue, DecisionHumanTask · TaskEvent

Decision

The binding approve, return or reject. It is kept by the department that owns it, PMO or Finance, not by the factory.

Shown on Decision, Work itemCommercialDecision · ChangeDecision · InvoiceReview · PaymentDecision

Department record

The business thing itself: engagement, costing, milestone, change request, issue, invoice, receipt, forecast.

Shown on Registers, Project journeypmo.* · finance.*

Document and version

A controlled document with numbered versions, a template and an audience (internal or client). Review always targets one exact version.

Shown on Document reviewdocuments.Document · Version · Template

Send job and receipt

One attempt to send something out, and the proof it arrived. If the outcome is unknown, the system checks before it ever resends.

Shown on Exceptions, Work itemPublicationJob · PublicationReceipt · InvoiceDelivery

Rule

A configured business decision such as an approver, rate, deadline or threshold. Lifecycle: draft, validated, active, then replaced or revoked.

Shown on Setuppolicy.Configuration

Access

Who may do what on which workspace, checked on every record and action. Text in a document or an agent's output can never grant it.

Shown on Setupidentity.Grant · TenantAuthority

3 · Step types

Every line is built from the same 15 steps

The code defines 15 reusable step types. A line is a sequence of them, so an invoice and a project closure are the same kinds of step with different content. Numbers are the code's own IDs (ACT01 to ACT15).

Design 15 step components, not 25 line screens. Each line's work item page then becomes a sequence of these components. A new line, or the 14 BaaS processes later, reuses them instead of needing new screens.

01Defined, not built

Classify intake

Intake

Work out what an incoming request is. Unclear identity stays unresolved.

02Defined, not built

Resolve workspace and process

Intake

Link the request to one project and one process. Never merge when unsure.

03Partly built

Plan the next permitted step

Coordinator · O01

Choose only steps that are allowed right now, and record the plan before acting.

04Partly built

Investigate evidence

Investigator

Read permitted sources. Every claim cites an exact source version.

05Partly built

Request missing information

Investigator

Open one internal task for the right role, or stop with Owner needed.

06Partly built

Reconcile PMO facts

PMO

Check that milestone, evidence and handoff all agree.

07Partly built

Link current source evidence

PMO

Attach the latest version of a source without rewriting it.

08Partly built

Prepare controlled output

Department

Draft the document, report or invoice from configured templates and rules.

09Partly built

Assemble decision packet

Department

Put together everything a person needs to decide, tied to one exact version.

10Partly built

Resolve who decides

Service

Work out the eligible approver from configured rules. No agent involved.

11Partly built

Carry out a permitted command

Executor

Do the approved action through the department service, such as issuing an invoice.

12Partly built

Reconcile an uncertain effect

Exceptions

Find out whether a send really happened before anything is retried.

13Partly built

Verify the outcome

Verification

Check the output against its decisions and receipts. Only this makes it Verified.

14Defined, not built

Diagnose an exception

Exceptions

Explain why something is stuck and what would unblock it.

15Defined, not built

Explain the history

Explanation

Tell the story of a work item in plain language, from its records.

8 · Gaps to settle

Decide these before the screens harden

Each gap changes what some screens have to show. Tags say who closes it: PSL for a business decision, Design, or Backend. The first three were decided on 7 November 2026.

Decided · 7 NovBackend

Alerts go out on WhatsApp and email

People get a WhatsApp message and an email when something is waiting for them, with a link into the app. Decisions still happen in the app, where access is checked.

Still needed: a WhatsApp Business number and provider, Meta-approved message templates, a sender email address, staff numbers and opt-in. Built against mocks until the connections are approved.

Decided · 7 Nov

Staff record client responses

Clients stay outside the app for now. Staff record what the client did, when and who, upload the proof, and confirm it's genuine.

Design: one “Record client response” component, reused for SOW, PRD, UAT, go-live and change sign-offs.

Decided · 7 Nov

Test templates for now

We create clearly labelled test templates for every document the factory produces. PSL's real templates replace them later as new versions.

Note: money templates get empty fields for amounts, tax and terms. Values come from rules PSL configures, never from the template.

PSLDesign

Day one is all “Owner needed”

13 decision groups (57 settings) are open: approvers, delegation, deadlines, pricing, invoice terms, payment exceptions. The setup pages read like engineering tools.

Design: a “set up the factory” journey as its own flow.

Design

Two products in one

25 factory lines sit beside about 35 workspace tools, across 191 page templates. People will feel the seam.

Decide: tools become stations inside lines, or a clearly secondary workbench.

DesignBackend

No whole-project view

Each work item belongs to one line, and a project crosses most of them. No screen shows the full journey.

Build: a Project journey screen fed by every work item in the workspace.

BackendDesign

Pages don't update themselves

Agents work in the background, but “Processing” stays on screen until someone reloads.

Decide: a small auto-refresh that fits the no-framework rule.

PSLBackend

No comment thread

Decisions carry notes, but there's no discussion on a work item, so the reasons will end up in WhatsApp and email.

Decide: whether a light thread belongs in the record.

PSL

Nothing can be “late” yet

Deadline rules are still open, so the app can't say anything is overdue.

For now: show age from timestamps; “overdue” waits for the rule.

Smaller gaps

  • The only search is on the work queue.
  • CEO approvals need a phone layout.
  • Every mock result must be visibly labelled as mock.
  • Navigation should keep room for the 14 deferred BaaS processes.

Answered on 7 November

  • Only PMs, Finance and HR log in. Engineering, QA and Security don't, so PMs record their sign-offs with proof.
  • Volume: a lot of work. Rough numbers still to get.
  • Devices: all kinds. Every screen must work on phone, tablet and desktop.
  • Still open: whether the CEO logs in, and the brand guide. Both are on the approvals worksheet.
