Engineering design: reuse append-only Evidence versions plus exact domain Audit provenance for typed packets/alignment/comparison/readiness records. Capture unknown source/contact/question values explicitly before owner rules. Bind both distinct current formal alignment meetings and action heads to one current packet. Generate correlated P02 requests against an immutable requirements wrapper containing the exact packet ID/hash; source roles remain separately enforced. Runtime readiness checks exact current requests, source observations/contracts/authority, meetings, engagement, action heads and configured gap/contact/age rules. Evidence text or a generic uploaded JSON body cannot create domain provenance or approval authority.

Typed owner criteria define which question states block, contact requirements, allowed linked-action states, alignment age and the actual authorized post-signature comparison reviewer. Build criteria UI/validators/fixtures/tests without installing owner values. Missing criteria holds readiness, not packet or meeting capture. A changed packet after signature needs current comparison evidence; unchanged readiness prepared before signature does not force planning to restart when the subsequent signature arrives. A recorded difference holds the dependent adoption until existing controlled change/commercial work resolves it. No inferred contract precedence.

Expose a server-rendered planning workbench and bounded internal investigation over the same current references/holds. Bridge current readiness evidence into the existing delivery scope-baseline source path, with current lineage revalidation at planning guards. Operational native source verification remains independently required by delivery; this packet must not manufacture it. Preserve all original process identities and all financial/signature/release controls.
