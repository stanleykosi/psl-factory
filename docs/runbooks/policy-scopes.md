# Explicit policy source scopes

This is an implemented engineering interface over guide10, not a new business precedence or appointment rule. Owner values remain deferred. No organization, person, business role, grant, policy, key or provider is installed by this increment.

Open a case's Policy configuration, save a typed component envelope and validate it. Open `/cases/<case UUID>/policy/scopes/` to create a source. Its configuration is then frozen; publish/revoke using the independent scope lifecycle. A source version contains the independently versioned kind/ref, explicit authority case, component configuration, contextual binding paths and immutable actor/state history. Its effective window and reviewed domain implementation come from the configuration. Publishing does not activate a local business policy.

Organization references equal the authority case's tenant. They are reusable only by explicit application within that tenant and synthetic/operational classification. This is an explicitly selected source namespace, with current case-scoped publication rights; it does not infer organization-wide business authority. Project references equal their project case UUID. Service references equal their support/service case UUID. Contract references are `evidence:<recorded SOW ID>` in the authority case. Contract sources work before signature without signing a SOW or changing planning-before-signature controls. Project, contract and service sources retain their exact case; rebinding those subject identities across cases is unavailable.

For application, enter the exact source version ID, a target-local policy-decision evidence record and explicit contextual bindings. Current source `case.read`/`policy.read` and target `case.read`/`policy.configure` are required. Every declared contextual path must be bound explicitly on a cross-case application. A binding identifies an existing scalar leaf in the list of resolved policy values, such as `/0/due_time`; it cannot replace objects, arrays or implementations. Scalar types are preserved and JSON must be finite and bounded. Source paths are immutable source-publisher declarations, not arbitrary target overrides. The resulting referenced contents are registered under new target-local immutable references, then checked by the same actual domain validators in that target context. Original reference content, hashes and evidence remain unchanged.

The result is a normal local Configuration draft. Validate and activate it separately in Policy configuration. Existing decisions, snapshots and jobs keep pinning normal local Configuration IDs. No source scope wins automatically. Exact source lookup is `resolve_source(actor, authority_case_id, component, kind, ref, effective_time, expected_revision)`; local workflow resolution remains `resolve(component, case, ...)` against explicitly materialized versions.

New execution checks origin lifecycle, effective window, current publishing/applying actors and exact grants, tenant/classification, domain validation and bound-value integrity. Source replacement, expiry or revocation makes the derived version unavailable, without fallback to an older or broader source. Local replacement is an explicit new reviewed configuration or application. Historical records are not rewritten. Transactional workflow resolution and source lifecycle changes share PostgreSQL advisory locks at the local commit boundary. Existing receipt-first workers still reconcile committed effects before checking current execution authority.

The scope workbench shows current accessible applications and independent lifecycle controls. Its bounded internal A04 investigator explains held origins and suggests human reassessment; it has no effect tools, model-provider call or activation capability. Impact reporting is bounded and shows only cases the current viewer can read through both case and policy grants. The linked domain impact workbench now provides nine declared PMO/Finance/BaaS adapters and reviewed observed-head assessments; see docs/runbooks/policy-impact-reassessment.md. Other domain consumers remain explicit unknown coverage, not implied by a list of configuration IDs.

Native backup preserves immutable scope history but removes grants and makes restored accounts inactive/unusable. Recovery targets remain quarantined. Archived source publication and application records cannot supply current authority. A fresh operational authority and separately reviewed reconstitution are still required.

Synthetic fixtures and PostgreSQL service/UI/concurrency/recovery tests demonstrate this infrastructure. They are not real owner, provider, oracle, SSO, security/load or user-acceptance evidence. All122 process acceptance statuses remain partial.
