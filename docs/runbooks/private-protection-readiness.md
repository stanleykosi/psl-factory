Engineering contract: bind one actual private isolated metadata restore job to an immutable integration contract. Source-backed Finance/PMO ownership and human decisions remain unchanged. Capability evidence does not authorize accounting, full database recovery, deployment or user acceptance.

1. Capture an accepted private packet into an explicit portable metadata plan, export it and create a sealed backup through the existing operator workbench. Reserve its exact isolated restore job. Never point a drill at the application database.
2. In `/cases/<uuid>/integrations/`, select that exact private restore job when capturing the internal protection contract. The typed agent prepares the contract; services enforce current grants, case, source lineage and immutable binding. Capture is available before missing private readiness policy. Generic contracts cannot collect private restore receipt provenance.
3. Draft `INT.private_protection_readiness` using `schema:psl/private-protection-readiness/v1` and validate/activate through the configuration lifecycle UI. Supply exact job inventory, actual probe principal/role, independent reviewer/role, freshness and bounded lease/attempt values. Both principals need original private source/export grants and integration actions. The unset fixture is not a real appointment. This component is independent of the original Finance readiness policy to avoid invalidating the accepted source packet.
4. Reserve health and receipt probes using the existing durable worker. Health authenticates the configured isolated database session and scoped receipt SELECT capability; receipt probes use only the exact bound restore job. Provenance contains IDs, hashes, target identity, found/not_found and explicit no-authority/no-full-restore flags. It contains no sealed manifest bodies, quotes, document sections or credentials. A not_found result proves a lookup capability, not that a restore occurred.
5. Assess current evidence and obtain a separate configured human review. Explicit enrollment applies only to the exact private restore job. Public protection enrollments retain their original behavior; unrelated exports/backups and unenrolled private restores do not acquire this dependency. Original source/owner/OPS policy checks remain independent.
6. Actual restore changes receipt provenance from not_found to found and makes old capability assessments stale. Fresh probes/assessment/review are needed for current use. Owner withdrawal, source supersession, grant revocation, policy revision, changed target/credentials or expired evidence hold current use without rewriting history.

Read/recovery boundaries: all private source/report/UI/agent paths recheck original source/export grants, including cached and idempotent reads and prior reference participants. Source withdrawal denies historical reads; owner withdrawal leaves source-authorised historical capability reports visible but held. Unknown probe outcomes reconcile committed observations before authority/policy/attempt gates. Do not clear attempts, cancel uncertain work or create duplicate restore effects to force a green report. The bounded live agent investigates and prepares contracts; it cannot approve, restore, probe or force retries, and stores no generic AgentRun.
