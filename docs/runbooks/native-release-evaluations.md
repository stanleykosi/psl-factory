# Native payment and hypercare evaluation previews

Engineering previews reuse the existing native service calculations. Owner payment-basis, qualifying-funds, role, hypercare-duration and metric values remain versioned policy decisions. Synthetic tests are not operational policy or live evidence.

Select `payment.assess` with an exact delivery dossier and billing coverage, or `hypercare.evaluate` with an exact dossier, in the reviewed pilot binding workbench. The identifiers must belong to the selected case; PostgreSQL enforces the closed argument types and subject scope independently of the form validator. Current source read permission is checked before source lookup. Review permission alone is insufficient.

`READY_AT_OBSERVATION` describes whether the native **assessment can be performed**. It does not declare that a payment expectation or hypercare criterion was satisfied. Payment output explicitly distinguishes `UNKNOWN`, `BELOW_EXPECTATION` and `MEETS_EXPECTATION`. Missing payment basis remains unknown; it does not become zero. Hypercare qualification remains `null`, `false` or `true` as returned by verified Engineering/Infrastructure source evidence and configured criteria. Unknown or failed qualification cannot satisfy the existing closure service.

The projection returns bounded status, identifiers, policy pins and hashes; no payment amounts, debt detail, metric payloads or document bodies. No assessment record, human exception, release reservation, deployment, debt waiver or closure record is created. Native services retain their own permissions, transaction locks, evidence requirements and independent control checks.

Independent review and A04 investigation can explain the evidence only. Source revisions, policy successors, revoked source access and other native context changes require fresh observation. Human decision interfaces remain the existing source-owned workflows. No retry or dispatch tool is added here.

Actual PostgreSQL results and preservation evidence are indexed in BUILD-TESTS.md. Main-server redirect checks do not constitute a supervised live pilot.
