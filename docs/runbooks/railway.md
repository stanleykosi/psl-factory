# Railway deployment

The PSL Factory project runs a public HTTPS web service, a private worker, and a PostgreSQL service with persistent storage. The web service mounts its own volume at `/app/.runtime` for local operator artifacts. The worker handles bounded batches of milestone handoffs, controlled publications, invoice jobs and department approval routes. Run other workers from their documented, scoped management commands.

Case workspaces link to **Files and agent work**. The private `psl-uploads` bucket stores file bytes. PostgreSQL records the uploader, case, checksum and job state. The web and worker services use bucket variable references prefixed `PSL_UPLOAD_`. The worker alone holds `OPENROUTER_API_KEY`. Both services use `OPENROUTER_MODEL` to select the test model. Eight role instructions share one worker. OpenRouter receives only the requesting user's selected synthetic case text. Agent work supports UTF-8 text, CSV, Word, Excel and PDFs with selectable text, within the extraction limits. Drafts resolve source line numbers to exact excerpts. A person can record a review and retain the draft as case evidence. The page links to each role's native workspace. Those links and the reviewed evidence are the current handoff.

- Web starts after Django migrations succeed. Configure the Railway health check at `/health/` with a 300-second timeout. Keep one web replica for this startup migration and volume arrangement.
- Set `PSL_ENV=production` and a strong `PSL_SECRET_KEY` on web. Reference the same secret from the worker and set `PSL_SERVICE_ROLE=worker` there. Give both services private PostgreSQL host, port, database, user and password references from Railway.
- Run `railway up --service psl-web --environment production --detach` from the reviewed checkout. Verify migration completion, health, login and static files. Then run the equivalent command for `psl-worker`. Keep the worker private.
- Provision named accounts through a Railway shell. For a synthetic-only walkthrough, run `python manage.py seed_demo --username <name>` and deliver the generated password privately. For operational use, create named accounts and configure reviewed tenant and case access. Keep synthetic acceptance data in a separate environment before loading operational data.
- On **Files and agent work**, review a cited draft and then confirm its workflow handoff. The form asks for any required human inputs. The page records the native record number and preserves it on repeat submission. Release evidence enters as an unverified lead. Finance recognition enters as a preparation packet.
- Core hosting uses no third-party API keys. Actual provider actions require the approved configuration and secret references for the selected integration. See `PSL_INTEGRATION_PROFILE` and `PSL_QUICKBOOKS_MCP_PROFILE` in the runtime loaders. Recovery profiles and an isolated restore target require a separate setup and rehearsal.
