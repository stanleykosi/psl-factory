# F33 project progress and recognition review

Source-backed boundary: contracts/process-map.json#F33 and reference/03-definitions/Finance.json#F33 describe the manual fallback for inaccessible PMO project/price/progress evidence. PM attests progress; Finance owns recognition policy and accounting decisions. Transcript progress percentages are examples. Cash, project estimates, completion, acceptance and recognised revenue are different facts.

Engineering design: prepare a finite, dated project/period packet. It pins the current signed planning/commercial baseline, scoped evidence hashes, optional AF13 source/version provenance and PMO milestone completion. Explicit access/contact context preserves the manual route. Typed facts reject cash evidence labelled completion. Missing baseline/progress/price and declared contradictions remain visible; capture is allowed while incomplete. No reported percentage or cash amount is parsed into a recognised amount.

Configure F33.authority_rules with actual human PM/Finance purpose assignments plus D05 scoped role assignments and per-action grants. Configure F33.recognition_review_rules with exact recognition_policy evidence, required categories, independence and decision-reference criteria. Both are separately versioned and use the shared validate/activate/revoke workbench. No actual owner or accounting policy is supplied by the fixture. The interface configures review requirements, not an executable recognition method.

PM attestation -> durable local request/inbox -> Finance receipt -> Finance reviewed/return/disputed disposition. A request is an immutable row committed in PostgreSQL and visible in the same database inbox, with no remote uncertainty. No external adapter, email delivery or accounting write is claimed. Exact retry keys return the historical receipt; changed actor/intent/evidence is rejected. New packet/source/baseline/attestation/authority/criteria invalidates current use without changing historical decisions. Receipt is receipt only. Missing recognition rules hold only reviewed completion, while Finance can return/dispute evidence with configured responsibility.

UI: /cases/<case UUID>/finance/recognition/. Capture evidence in the shared case screen first; packet/policy schema details and fixtures/recognition-review.json document the shapes. Source and owner review is available through the AF13 link. Finance decision references are recognition_decision evidence; they preserve a human memo without posting a journal. Scope/status exports omit underlying source bodies and packet fact fields; human review notes remain scoped case data. Actual accounting execution/native authenticity and numerical oracles remain separate engineering/evidence work.

The deterministic A02/A07 investigator cites selected evidence IDs/categories, identifies packet gaps/contradictions and drafts PM follow-up questions. It cannot attest, approve, activate policy or change money. Local adapter/tests do not establish real-provider evaluation or operational owner acceptance.
