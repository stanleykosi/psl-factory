Engineering design: append typed details to existing immutable native assessment/execution records, with additive migration0043. Normal changes require each team's discipline statement and timeline, cost/resource, risk and dependency statements. Infra explicitly supplies true/false/unknown production applicability; Engineering supplies exact proposed scope identifiers. Existing Product/Engineering/conditional decisions pin these assessment IDs, including their scope statements. These identifiers are human-authored comparison keys, not machine interpretation of free text. No department threshold, currency rule, actual approver or deployment policy is supplied by code.

Missing details on old records remain readable history and unknown for new Normal authorization. No migration backfills false, no impact or approved scope. Standard and Emergency contracts are not changed by this bounded increment.

An updated plan event creates a native evidence amendment containing the exact owner plan content/reference/hash, current baseline, authorization, assessment IDs and approved timeline statements. This does not silently replace a signed baseline. Existing commercial adoption remains its only replacement route. The existing native period-report service copies the amendment into status and timeline sections and pins execution history. Timeline-impact completion requires a current weekly client report that actually displays the exact approved impact and plan reference. Native notice drafting requires the intended audience to display the approved timeline; publication preflight and closure recheck its actual rendered text. Review/publication/recipient receipt controls remain unchanged. Report timeline snapshots label current approved, held and superseded sources explicitly and participate in native report staleness, including authority withdrawal without a new decision row.

Engineering supplies actual scope identifiers with implementation evidence. Unknown or incomplete scope holds completion. Additional identifiers are recorded as a deviation and hold that authorization immediately, including after later apparently in-scope evidence. A new revision must return through assessment and prescribed authority; history cannot be retroactively normalized. QA validation still follows the latest implementation.

Production implementation evidence can be recorded without claiming permission to deploy. Completion then requires an explicit same-case native delivery dossier and `delivery.readiness_inputs` over its current baseline, candidate, upstream and GLPI decisions. Engineering explicitly pins the actual implementation candidate to its authorization/event, and the selected P32 dossier must identify that exact candidate. Same case and baseline alone are insufficient. Missing candidate linkage remains unknown. The recorded readiness snapshot must remain current. This reuses P32 and does not create a second approval engine or a deployment command. Unknown Infra applicability holds the dependent impact decision, not unrelated work.

Both native and factory consoles accept the new owner fields. Scoped factory investigation sees explicit owner outputs and implementation comparisons; it cannot create human assessments or decisions. Weekly report and native production-readiness links identify the next existing human surfaces.
