# Accepted Finance / AF13 metadata publication

This is an engineering contract for controlled local metadata disclosure. Source-backed Finance ownership, human owner validation and system-of-record boundaries remain unchanged. A native accepted packet does not prove native QuickBooks authenticity, accounting posting, whole-product acceptance or operational readiness.

Use `/cases/<case>/finance/accepted-documents/` from the Finance acceptance workbench. Register an immutable `accepted_finance_metadata` template with `required_fields:["executive_summary"]`, `internal_review_required:true` and explicit supported audience fields containing only `executive_summary`. The native adapter generates the exact closed metadata payload; generic text drafting cannot populate it.

Configure F01.accepted_publication through the private configuration form and existing policy lifecycle screen. Supply exact handoff and template inventories, selected closed metadata keys, one audience, exact authenticated recipients, distinct Finance reviewer/publisher and review lifetime. Both publication principals require current native private source access and actual D05 Finance authority. The original Finance owner is distinct from both. D11 independently enables the template, retention and exact audience recipients. A recipient requires only the explicitly configured audience receive grant for the curated metadata; this grants no raw Finance access. The fixture has no actual appointments, inventory or audience defaults.

The original Finance owner prepares a document only from a currently confirmed native handoff acceptance, including its original source/provider/result/draft/package/AF13/decision/authority/freshness checks. A separate human reviews the exact payload. A distinct configured human reserves publication. Shared workers deliver to the existing internal recipient inbox; this adapter sends no email or external request. The receipt contains only configured metadata fields. Source or audience changes hold new delivery; latest negative human decisions and superseded versions never fall back to an older approval.

A lost acknowledgement is reconciled by original publication key and committed receipts before source checks or attempt budgets. Do not reset uncertain jobs or create replacement intents to guess an outcome. An unchanged held job may retry within its original attempt budget through the source-authorised operator interface. Changed snapshots require a new reviewed document revision. Unknown jobs cannot be cancelled or reset. Historical source-authorised staff reads remain possible; current-use findings are evaluated afresh. Recipient inbox access rechecks the current matching publication policy and receive grant; it does not require perpetual source freshness for an already committed disclosure.

Generic document lists, generic agents and generic evidence omit native metadata drafts. The private workbench/report rechecks original source scope and uses `Cache-Control: no-store`. Shared operator inventory and cached export reads recheck native publication access. No generic AgentRun stores private metadata findings. The bounded native agent prepares deterministic metadata or investigates current holds; it has no human review or publication tools.

Verification is recorded in BUILD-TESTS.md. Authenticated loopback provider fixtures and real PostgreSQL/Django HTTP are distinct from real-provider, native QuickBooks, business-owner and deployment acceptance. No old main-case evidence is renewed or seeded by this increment.
