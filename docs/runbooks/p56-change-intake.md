## Source-backed behavior

P56 in contracts/process-map.json and reference/12-payment-exception-policy/process-execution-bindings.json requires a CR reference, original requestor, date raised, description, reason and affected project/module. A01 may extract fields and suggest Standard/Normal/Emergency with cited basis. The PM classifies. Classification needs no approval and never grants implementation permission. Source authority and unresolved Standard/Emergency controls remain unchanged.

Previously, pmo-change/v1 selected an already classified ChangeVersion. The new request-first entry retains a private original request and immutable receipt, performs bounded local synthetic extraction, allows explicit unknowns and human correction, and binds PM classification to the native ChangeVersion. The existing native ChangeRequest remains the only CR register.

## Native ownership and data

- Evidence/Audit retain raw source, authenticated capture, immutable hash, submission identity, correction lineage, extraction attempts and cancellation.
- AgentRun retains the private typed A01 result. Quotes must support extracted values; a category requires supporting source text. Extra command fields and invented citations are rejected. The labelled local mock is explicitly synthetic and is not an evaluated language model.
- ChangeIntakeConfirmation uniquely binds one receipt and one native ChangeVersion, the selected extraction or explicit manual capture, confirmed field payload/hash, PM and policy pin, and the new controlled-change FactoryWork when applicable. Original requestor/date raised remain distinct from actor/capture timestamp.
- Native log_change checks current PM assignment for all callers. This is an ownership check, not a new approval task. Existing legacy records remain readable and explicitly show missing structured requestor/date facts rather than claiming actor/time are substitutes.
- Manual PM capture remains available if extraction is unavailable or its bounded local attempts are exhausted. No live provider is connected and no external request is sent.

## Connected output and recovery

A new Normal or Standard classification starts existing pmo-change/v1 without authorization. Its native owner assessments, decisions, templates, Standard catalogue, publication review, implementation evidence and signatures remain separate controls.

Emergency classification retains its receipt and incident reference and links to the actual native P61/P62 entry. It neither starts ordinary change authorization nor creates an Emergency implementation. A new revision of an existing CR requires its exact current revision; it retains the original factory business identity and links to that work's explicit source-correction controls. Existing effects must be reconciled there before replacement.

Submission replay and confirmation replay return their original results; changed payload/initiator conflicts. Logging, confirmation binding and new factory creation commit together. A lost HTTP response is reconciled by reading the same receipt, not re-logging. Unconfirmed source correction retains the predecessor and shares its local attempt ceiling. Cancellation cannot undo a logged change. Generic readers do not expose private raw requests or extraction bodies.

Extraction is local, bounded, and serialized by the existing case lock. There is no external effect, paid token call or second orchestration/lease framework. A process failure before local commit may safely repeat the local calculation; retained failed validation attempts are not erased or given a fresh allowance by source correction.
