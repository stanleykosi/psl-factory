## Connected output and recovery

A new Normal or Standard classification starts existing pmo-change/v1 without authorization. Its native owner assessments, decisions, templates, Standard catalogue, publication review, implementation evidence and signatures remain separate controls.

Emergency classification retains its receipt and incident reference and links to the actual native P61/P62 entry. It neither starts ordinary change authorization nor creates an Emergency implementation. A new revision of an existing CR requires its exact current revision; it retains the original factory business identity and links to that work's explicit source-correction controls. Existing effects must be reconciled there before replacement.

Submission replay and confirmation replay return their original results; changed payload/initiator conflicts. Logging, confirmation binding and new factory creation commit together. A lost HTTP response is reconciled by reading the same receipt, not re-logging. Unconfirmed source correction retains the predecessor and shares its local attempt ceiling. Cancellation cannot undo a logged change. Generic readers do not expose private raw requests or extraction bodies.

Extraction is local, bounded, and serialized by the existing case lock. There is no external effect, paid token call or second orchestration/lease framework. A process failure before local commit may safely repeat the local calculation; retained failed validation attempts are not erased or given a fresh allowance by source correction.
