# BaaS reconciliation and Engineering requests

This is a tested local subset of B04–B07, not native reconciliation acceptance. The source requires Engineering-mediated correction; it does not prescribe a new mandatory Reconciliation certification role. ARCH099–102 separate source facts, finite engineering choices and actual evidence.

Open a support case's **BaaS reconciliation** workbench. Capture versioned `reconciliation_input` evidence with explicit ledger/settlement/queue source, aware as-of/observation timestamps, partner coverage/completeness and bounded transaction rows. Unknown amounts stay null; duplicate rows are preserved for investigation. Capture works without configured policy. These supplied JSON sources are not authenticated bank data or a native Excel adapter.

Register/draft/validate/activate exact artifact references through the policy lifecycle. `D09.reconciliation_contract_ref` uses `schema:psl/baas-reconciliation/v1`: exact declared sources, precision/tolerance, freshness, pending age/states, disjoint settlement statuses and optional attestation kinds/roles. `D09.queue_state_command_map` uses `schema:psl/baas-queue-commands/v1`: actual Engineering recipient, execution source, retry/lease bounds and explicit command rows. Each command selects findings, current queue prerequisite, amount method/limit, account route, approver/sender/verifier roles and separation. Current D05 role-principal assignments and actual per-case action grants are also required. No synthetic values should be installed as operational rules.

Attest exact supplied source hashes only where configured, then compare explicit batch versions. Findings show settlement confirmed/not confirmed/ambiguous, exact amount differences and independent queue readiness/age. Missing/duplicate/stale/conflicting rows, unknown amounts or unsupported source precision never become zero or a guessed match. Queue duplicates do not erase independently supported settlement findings. Each immutable investigation binds captured inventory, selected versions, attestations and current rules. Additional captured versions, changed policy or lost authority invalidate dependent use while preserving history.

Capture exact `corrective_request` evidence against a transaction in an investigation. Human approve/return/reject binds its exact current snapshot. Approval alone has no financial effect. Reserve a durable Engineering handoff under current configured sender/recipient authority; run `.venv/Scripts/python manage.py work_corrective_requests --limit 1`. The local adapter delivers only the minimal reviewed command to `/baas/engineering/inbox/`. It cannot credit a customer, move funds or modify the business queue. Tenant-wide operation and transaction/kind/transition reservations prevent competing deliveries, including across cases.

Workers use leases/fences, bounded attempts and receipt-first lookup. Unknown work holds competitors and cannot be cancelled optimistically. Held work supports explicit retry, cancellation or a new intent generation; proven delivery remains immutable after revocation or lost response. Native remote adapters must supply independently verified idempotency and reconciliation contracts before use.

Only the actual appointed recipient can record correlated `engineering_outcome` evidence. The payload must match operation, request hash, source and exact command. Unknown reports remain unknown. A configured human verifies exact terminal supplied evidence, after actual delivery, separately from request delivery; distinct verifier rules are enforced when configured. Conflicting reports remain history and cannot overwrite a verified terminal result. Human attestation does not establish bank authenticity. Refresh external sources after reported execution; this application never edits the business ledger or queue to make a finding disappear.

The cited A03/A05/A07 investigation reads source/decision/delivery/outcome lineage and proposes evidence refresh/follow-up. It has no approval, dispatch or execution tools. It is a deterministic bounded fixture agent, not a real-provider evaluation.
