# F35 HR-authorised read-only Finance handoff

Source facts: contracts/process-map.json#F35 and reference/03-definitions/Finance.json#F35 describe a separate HR-owned Finance view and uncertain proposed wider integration. HR owns staff facts/disclosure; Finance defines a justified purpose and sends corrections to HR. Medical/disciplinary fields outside a contract must not be accepted merely because a file arrived. No native HR API, actual Finance view identifier, real principals or retention values are supplied by the pack.

Engineering design: a versioned Finance need records entity, period/as-of, requested fields, per-field justification and actual recipients. Independently versioned F35.authority_rules and F35.disclosure_rules hold actual HR/Finance responsibility, exact supported source view and route, permitted fields/purposes/periods/recipients, opaque exact employee-key matching, inclusive/exclusive end-date semantics, freshness, retained-access expiry and correction route. The finite v1 interface supports employee_id/BU/effective dates plus explicitly justified and HR-authorised role/monthly_pay/currency fields. Pay is copied as a typed reported value, never calculated or used for an employment decision. Unknown BU/pay remains unknown. In this finite supplied protocol a null effective_until declares an open interval; it must not be used to disguise an unknown source date. Unknown/unmapped date semantics require source clarification or a reviewed adapter/schema extension. Other source schemas and native adapters require reviewed engineering.

Prepare an exact minimal contract under current policy; configured HR must approve that contract before capture. Capture is a bounded supplied JSON export through the HR-only action. The adapter has no source write/network capability. It rejects extra fields, malformed identifiers/types, duplicate employees, ineffective dates, future/stale extracts and wrong source/entity/period. Rejected attempts retain only a source hash and sanitised exception code, no row values. Accepted minimal rows live in dedicated Finance records, never shared Evidence/Audit/AgentRun bodies. Do not paste staff/payroll rows into the general case evidence form; shared evidence references are for safe need/source-contract/decision/correction metadata only.

Read access requires exact case/action grants, current nominated Finance recipient and D05 role, current HR approval/policy/source context, freshness and retention. Read operations take the same case/grant locks as disclosure changes. Metadata boards/form choices/inboxes/agents defer the private payload and fetch only timestamp/completeness JSON subkeys for freshness checks; boards never inline private rows; a separate no-store JSON endpoint checks every read. Read-only field/view permission does not imply salary permission or access in another case/purpose. Physical database copies persist under append-only history; the supported owner policy is restrict_after_expiry, not purge. Native deletion propagation, encryption/key management and production retention operations remain separate engineering.

A captured immutable row is a durable local Finance inbox entry, not an email/API delivery. Finance receipt is exact-snapshot acknowledgement only. Correction requests route to the configured HR inbox reference; HR links a later accepted source export, never a Finance edit to HR. The successor requires a new receipt and input references, preserves the old snapshot and invalidates old current-use allocation. Unknown external delivery is not fabricated for these same-database operations.

Finance staff/BU allocation reuses D07.authorized_input_refs and D07.effective_membership_ref through new typed exact snapshot/hash references. No staff master or raw payroll is copied into shared policy/evidence. The binding UI drafts references only after the current recipient receives the snapshot. The existing allocation engine rechecks access/receipt/freshness/current source; unit-per-subject weights are used only under an explicit D07 unit headcount rule. FTE, payroll inclusion, salary joining and historical restatement are not inferred. Missing HR basis holds the headcount pool while unrelated direct/fixed pools continue. Partial/unknown inventories, unknown BUs and zero denominator cannot become an allocation.

The bounded A02/A07 investigator reads metadata only, compares purpose/requested fields, flags unnecessary fields, missing policy/source-contract confirmation and stale/exception states, and cites need/contract/snapshot references. It reads no private rows and cannot authorise, expand disclosure, change source facts or process payroll.

UI: /cases/<case UUID>/finance/hr-handoff/ with links to existing Finance allocation, policy lifecycle and AF13 source validation. Synthetic shapes: fixtures/hr-finance.json. Actual PostgreSQL results are in BUILD-TESTS.md; mock/supplied sources and local deterministic agents are not native integration/provider/owner acceptance.
