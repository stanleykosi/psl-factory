# B14 private projections and reviewed draft reuse

Engineering implementation over the existing B14 services. Supplied intake claims are not a verified channel API or proof of message content. The local adapter projects only configured fields from an exact linked `SupportIntake`. It never dereferences `content_reference`, reads arbitrary Evidence bodies, or fetches remote URLs. `transaction_ref = null` stays unknown; explicitly selecting an unknown field holds projection instead of replacing it with empty text or zero.

Open `/cases/<uuid>/support/agents/`. Configure `B14.agent_projection` through its typed draft form and existing policy lifecycle. Inputs are exact intake IDs, allowed field names, purpose, actual projector/owner/reviewer IDs, independence, draft size and review lifetime. All principals need their actual D05 Support authority and native Support purpose assignments; source and action grants remain separate. Fixture `fixtures/support-agent.json` is explicitly synthetic with unresolved IDs, never an operational recommendation. Missing native rules hold projection/reuse; intake, owned case flow and policy configuration remain available.

The source case must have a current reviewed flow, linked intake, active unmerged state and named owner matching the configured draft owner. The immutable source binding pins source hashes, links, flow review, head event, policy versions, purpose, field inventory and actual projector/owner authority. A new event, link, owner, rule, role or source grant makes the old projection unusable for new sends/reuse. Capture a fresh projection with a new intent key and review it. Each source packet is private `agent_private_support` evidence linked one-to-one to its trusted projection binding. Manually labelling evidence with that kind does not confer native provenance; the generic projection interface cannot reproject it.

The existing private-evidence gateway handles the exact B14 projection: `INT.agent_data` still needs exact packet/source/process/purpose/provider policy, sender/reviewer roles and budgets. Current reviewed provider readiness and deployment bindings remain necessary. Native `support.read` and `support.private.read` are checked for sends and private source/result access, alongside data grants. Receipt-first worker recovery can reconcile an already accepted request after revocation; that does not restore source visibility or permit new sending/reuse.

After a current human confirms/corrects the extraction, the bounded drafting tool copies only reviewed fact quotations into a private draft owned by the configured current case owner. It does not copy model uncertainties into a response. The result-review ID, source binding and actual owner/policy are pinned. Stable references make repeated reuse idempotent. Human edits create new immutable draft versions and require a fresh exact-version review. Return/withdraw retains all history. Private reports distinguish historical content from current approval.

Draft records are separate from `SupportEvent`, response evidence, first-response timestamps, publication and delivery receipts. Creating, editing or approving a draft sends nothing and cannot resolve a case, move funds or bypass Engineering corrective controls. No public AgentRun or generic document is created. Native projections and their input hashes stay out of generic source/timeline readers. Further outbound response release/delivery requires its own reviewed engineering path and actual configured destination contract.

Use the existing `work_private_evidence --case <uuid> --limit 1` for a scoped extraction queue. Never drain unrelated demonstration jobs or rerun one-shot seeds. Actual vendor/channel/message-body integration, real model evaluation, approved egress and owner acceptance are distinct from authenticated loopback mock tests. Preserve original process IDs and source snapshots; this bounded increment does not complete all B14 variants or the product.

The latest reviewed flow must also match the adopted head snapshot; re-review or policy replacement cannot silently migrate a case. Intake tenant must match the case. Original B14 summary independence applies even when the projection supplement asks for weaker independence. Approved/human-edited history remains immutable and privately readable, while current approval is recomputed. RUN162/163/164 prove the bounded implementation; see BUILD-TESTS for actual counts and durations.
