# Native Finance publication readiness and private provenance

This engineering interface proves bounded internal transport capability and exact recorded receipt provenance. It does not prove native QuickBooks authenticity, current Finance approval, external delivery, real owner acceptance or operational readiness. Finance source and human publication controls remain independent.

Start with an exact reserved accepted_finance_metadata PublicationJob. From the Finance accepted-documents workbench follow the private health/receipt readiness link. On the shared integrations page, select the optional native publication job when capturing an adapter contract. The selector contains only source-authorised native jobs. Configure the reviewed internal publication contract (family publication, internal_postgres_session_v1, internal:publication, runtime:postgres and the actual reviewed runtime principal/credential revision/protocol). No endpoint or secret is invented by this feature. Capturing a source contract is available before readiness policy; probing and native enrollment require configuration.

INT.adapter_readiness domain schema schema:psl/integration-readiness/v2 adds exact native_publication_job_ids inventory. Include that field in the shared typed policy editor to create a v2 registered reference; use the existing policy validation/activation lifecycle. Native policy requires independently configured actual probe/review humans, receipt probes and current original private Finance source grants. The fixture is unset and synthetic; it supplies no real people, source inventory or appointment. Existing v1 public/provider/other-family contracts remain usable. No additional policy component or financial rule was created.

Capture binds the exact immutable IntegrationContract to an exact native PublicationJob with a metadata descriptor/digest. Finance0050/0051 protect the binding and its case/source lineage. A native reference cannot be downgraded to a public reference, and source checks retain all historical native participants in that reference. A generic publication contract cannot probe a native Finance receipt or satisfy its readiness gate. Enrollment is per exact job: public documents and other native jobs acquire no dependency from this selection.

Reserve health and receipt probes. Health opens an actual PostgreSQL session, verifies the configured runtime principal/protocol and SELECT capability, and pins exact native source identity. It does not claim password authentication was proven. Receipt probes use the existing local publication adapter to verify complete matching receipts or recorded absence. Provenance contains IDs/hashes/expected recipient references, never outward payload sections, Finance quotations, credentials or draft bodies. A successful not_found observation proves a lookup capability, not delivery or acceptance. Actual receipt rows and hashes are exposed only through source-authorised private provenance endpoints.

Obtain the configured independent human assessment review, then enroll the exact contract. New native delivery checks that reviewed current capability plus the original Finance/package/acceptance/document/audience/publication controls. A receipt state/hash change makes the earlier readiness assessment historical: run a fresh receipt probe, assessment and human review. Do not edit old observations. Committed publication and probe effects reconcile by their original receipts before current grant/policy/readiness or attempt checks. Unchanged held native probes can retry within their original attempt budget; unknown outcomes require worker receipt lookup and cannot be force reset/cancelled.

Shared contract/observation/report/forms/guidance recheck current private source rights, including historical foreign-case participants. Native source events and evidence references are hidden from generic timelines; generic integration agents omit native records. Private bounded guidance writes no generic AgentRun and has no business-effect tools. Staff responses use no-store. Existing operator metadata exports continue to recheck native publication job access; they do not export private readiness bodies.

Use case-scoped readiness workers when intentionally processing a case. Never drain unrelated jobs, renew old evidence, reset attempt budgets, replay business effects or infer deployment/business authority from a capability result. Public publication receipt lookup uses the publication's stable operation key; it remains independent of native Finance enrollment.

Actual test results and preservation/source evidence are in BUILD-TESTS.md. PostgreSQL and authenticated loopback provider fixtures are distinct from real-provider, native QuickBooks, external channel and owner/operational acceptance. Full application recovery, deployment security, broader native source variants, load and UAT remain separate product work.
