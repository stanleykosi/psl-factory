# Native AF13 evaluation and pilot evidence bindings

Engineering implementation and operator interface. Exact-subject protocol v2 passed its recorded regression and recovery checkpoint; this document is not acceptance or owner policy. Current actual test evidence is recorded in BUILD-TESTS.md.

## Scope and authority

Existing AF13 source capture, meaning/expectations review, versioned package and independent acceptance remain the authority path. The native path reads actual source-owned workflow reservations and verified receipts; it never dispatches, retries, publishes, restores or supplies an expected verdict. Supplied JSON reports keep their existing classification and cannot establish operational native execution. A selected AF13 decision is not whole-product or deployment approval.

Acceptance criteria use the existing AF13.acceptance_rules component with artifact schema `schema:psl/validation-acceptance/v3`. `native_execution` declares the allowed closed families, explicit freshness_seconds, fixed native_source_receipt_only scope and expectations_before_reservation:true. No owner values or policy are installed. Missing criteria hold native evaluation/acceptance while source capture and unrelated workflows continue.

Native records reuse immutable ValidationReplay. Current-use checks cover exact case/source/subject, current source reader/recorder/acceptor rights, active criteria, current independently reviewed expectations, source head/fence/receipt, freshness, observed process startup/current build and classification. An active worker lock holds evaluation with NOWAIT. Review memoization lasts one locked command/report only, is invalidated by native review/evaluation changes, and cannot cross requests. Business services remain responsible for their own permission, arithmetic, decision and effect controls.

## Prepare expectations before execution

1. In the native domain workspace, prepare the input record that will identify the planned work.
2. Use the AF13 source-fingerprint action to read its exact identity. This action supplies no expected state/receipt outcome and schedules no work.
3. Record independent normal/exception examples including family, operation, state, receipt_present and subject_sha256, and obtain the existing owner meaning and expectation reviews.
4. Reserve/run work through its normal domain controls. Native evaluation must bind a source reservation or immutable reservation subject created after the reviewed expectations. Four old job models use their existing immutable subject timestamps; historical jobs cannot be retrospectively relabelled as independently tested new work.
5. A source-authorized recorder selects the exact package, example, family and job. The backend obtains actuals directly; a caller cannot upload them as native results.
6. A configured independent acceptor reviews the matching current evaluations for the selected scope. Unknown/leased/unexecuted work and stale criteria/source/permissions/expectations cannot establish acceptance. Proven financial effects remain unchanged.

State/receipt observations are local source facts. Internal handoff/note/publication acceptance is not an incumbent accounting write, customer-channel delivery, model-quality or business-oracle certification. The source identity is an observation-process build pin, not proof of which build originally produced a historical effect; execution_build_verified remains false. Separate deployment-owned independent worker observations and supervised operating evidence remain required where applicable.

Protocol v1 history is retained and source-protected. It lacks an exact planned-subject pin and is not upgraded by copying or editing a receipt. Current evaluation requires protocol v2 and appropriately reviewed source examples. A different successful job in the same case must not satisfy an example merely because its state and receipt presence match.

## Read-only pilot pack

Pilot contract v2 selects exact existing AF13 acceptance review IDs. The pack rechecks their native private access, current source/example/review heads and current acceptance; it reports source hashes, native evaluation references and uncovered process IDs. AF13 never depends on the pilot observation hash, so pack capture cannot manufacture or invalidate its own source acceptance. Revocation or a successor makes recorded evidence historical. A pilot pack cannot copy review authority or grant actions.

Existing application/cold recovery jobs may be selected as physical evidence. Their own services verify archive/managed attachment/isolated PostgreSQL receipts, independent review and current permissions; native database recovery retains whole-source authority, and cold recovery retains its separately provisioned fresh identity. Projection exposes IDs/hashes/booleans only. It never includes paths, database names, key material or archive bodies. File tamper invalidates the projection and a saved pack. Native isolated recovery keeps users/grants inert and does not activate production. Retention cleanup, monitoring/SLOs and external repositories remain separate evidence; deployment revision strings alone cannot prove them.

Native history, AF13 decisions and source-aware pilot contracts must survive actual PostgreSQL/attachment archive/isolated recovery while restored actors stay inactive, grants absent and the target quarantined. All build/coverage metadata must distinguish implemented software, synthetic tests, actual provider/integration evidence, missing owner values and supervised operating acceptance.
