# AF13 protection operator native readiness

Engineering implementation; verification results are recorded in BUILD-TESTS.md and the run evidence. This is capability evidence for selected metadata operations. It is not owner, business, operational or deployment acceptance.

In the case integration workbench, select **AF13 protection operator job** when capturing a contract. Choices show job number, kind, plan/version and status. Select the actual export, backup or isolated metadata restore job carrying `private_protection_packet_ids`. Existing Finance-only file/restore selectors retain their historical meaning. Mixed plans use the new selector and preserve separate Finance and AF13 inventory hashes. Capture is available before downstream criteria are configured. Human capture uses its own permission; typed agent preparation additionally requires the agent permission.

Use the code-owned internal protection adapter with health and receipt lookup capabilities. Runtime PostgreSQL revision, principal, contract version and independently provisioned target identities must match the actual environment. Contracts contain references and hashes, never credentials or arbitrary target URLs.

Configure `INT.accepted_protection_readiness` through the typed policy draft, validation and activation lifecycle. Supply the exact `accepted_protection_job_ids`, actual active probe/reviewer principals and D05 roles, independence, freshness, receipt, attempt and lease criteria. Both principals need original private source/export grants and their actual integration permissions. The reviewer cannot prepare the source operator intent, contract, assessment or observations. The fixture installs no values or people. This independent component does not revise original Finance/AF13 source, transport or owner criteria.

Reserve health and exact-job receipt probes, run the shared readiness worker, assess current observations and obtain the independently configured human review. Explicit selection enrolls that exact source job in dispatch gating. Other jobs keep their existing controls. A health check proves read capability for the reserved SQL session and, for backup, a read-only directory inventory. It does not prove password authentication, storage write permission or full recovery. Export receipts read immutable SQL artifacts; backup receipts reread actual sealed bytes; restore receipts query the independently provisioned isolated metadata database.

Changed source acceptance, grants, policy, target, receipt state, expired observations or missing/corrupt bytes hold new dependent work. Preserve historical records and use fresh probes and human review when needed. Return/withdraw decisions remain separately recorded. Historical access still needs every original reference participant/source grant. The live private agent investigates receipt/review/recovery state and prepares typed contracts; it has no effect/approval tools and stores no generic private AgentRun.

For unknown outcomes, let the durable worker reconcile the original committed observation or operator receipt before retrying. A committed observation can reconcile after revocation without granting new authority or resetting the original attempt budget. Preserve the original file and isolated receipt; do not overwrite conflicting bytes or reenact business jobs. Use the shared operator recovery interface for committed source effects.

The new proof is intentionally excluded from the AF13 acceptance-source adapter. Do not recursively attach it as another owner packet. Source packages cannot depend on the downstream native readiness component. Full database/application recovery, actual target authentication, provider quality, process-owner/SOP evidence, production identity/security/storage, load and UAT remain separate work.
