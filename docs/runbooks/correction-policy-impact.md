# Correction policy impact and reviewed reassessment

Implemented engineering interface, verified with synthetic owner configuration and real PostgreSQL/domain workers in RUN353. No business policy or operational acceptance is supplied by this interface.

The policy impact workbench offers `finance.correction_effects` only to a current Finance reader with current case/policy/source access. Select an affected local policy and its reviewed active successor, exact policy-decision evidence and an explanation. A second authorized human records accept/reject/defer for the observed heads. Acceptance does not approve a correction, alter debt, reserve/retry a job or deliver a note. Use the linked financial corrections workspace for source-owned action and receipt-first recovery.

The adapter follows adapter/identity, correction method, issuer authority and correction-review policy pins from actual application reservations into note-delivery reservations for the same correction. JSON numeric source IDs stay numeric. It excludes ordinary invoice issue/delivery jobs, which retain their own adapter. Projections contain IDs, states, review/source/reservation heads, receipt hashes and canonical acceptance links; amounts, legal-note text and financial payloads are omitted.

Application and note delivery have independent exact-job receipts. A canonical correction acceptance can be visible alongside a retired reservation without that reservation inheriting the successful successor's receipt. Pending, uncertain, committed, committed-awaiting-reconciliation and retired states stay separate. Later policy changes do not erase canonical debt or proven receipts. A lost reply is reconciled by the native worker's lookup before any further dispatch. The metadata observation and bounded A04 investigator have no effect tools.

Reassessment locks selected mutable jobs with NOWAIT while normal case/authority locks apply. A worker lock conflict requires refreshing the assessment; it cannot force a concurrent dispatch. New source/review/reservation/receipt heads invalidate an old assessment. Current Finance and scoped-source access is checked again on page, review, agent and inspection. SQL and application selection accept only the ten closed impact adapter keys, with no duplicates; policy0008 is a forward registry-function migration and prior applied files remain unchanged.

Test evidence distinguishes actual internal workflow execution from synthetic principals/owner values and controlled transport faults. Internal note storage is not incumbent or customer-channel acceptance. Controlled-document audience, private Finance/payroll/HR/BU consumers, other effect variants and undeclared indirect dependencies remain explicitly uncovered. Owner values remain deferred; existing correction policy validators and source-owned authority continue to gate only their dependent runtime actions.
