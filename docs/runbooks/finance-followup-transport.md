# Finance follow-up transport

This is PSL's authenticated inert metadata protocol. It delivers the exact physically published investigation companion into a currently authorized PSL Finance source inbox. It proves neither a vendor/bank effect nor a Finance owner decision, release authorization or debt waiver.

Configure current source D05 role/principal and explicit case/action grants, then draft/validate/activate OPS.finance_followup_intake on the source case. The configuration screen accepts actual evidence, principal, sender/destination, variants and bounded signature window. Missing configuration holds inbox intake, not ordinary Finance work. Source receipt history and manual supplied intake remain visibly distinct.

Configure OPS.finance_followup_transport on the independent recovery control case with sender/destination, reviewed endpoint/key references, bounded lease/attempts and exact classification. Reserve the published packet in its native Finance workbench. Run `python manage.py work_finance_followup` in that independent control deployment. Existing cold-control quarantine and current purpose grants are mandatory. Investigation offers no financial effect tool.

Deployment setting PSL_INTEGRATION_PROFILE points to an existing reviewed JSON file with closed endpoint, secret-reference and Finance sender registries (see config/integration_runtime.py). Keys are read from named environment variables; no secret belongs in business configuration, URLs, artifact metadata or build records. Sender registry pins exact case IDs, classification, credential revision and destination. Operational intake requires HTTPS; synthetic loopback is for tests. The client rejects inherited proxies/redirects and bounds response size/time. Clock synchronization is required for signed request freshness. Deploy the matching protocol on both sides; this is not an assumed QuickBooks/bank API.

UNKNOWN means reconcile the original signed source receipt first. Do not replace its operation identity, delete the receipt, waive debt or replay archived effects. The worker looks up receipt evidence before trying a new source write. An acknowledged request can remain without any owner disposition. Revoking only new-intake permission preserves historical signed lookup; revoking the source's read identity, key/case binding or relevant policy may hold lookup as well. Such a hold cannot justify force delivery. Obtain fresh reviewed deployment authority and reconcile without rewriting history.

Tests use actual PostgreSQL and a separate actual Django source HTTP server, synthetic credentials/principals and controlled fault injection after source commit. They do not establish operational identity issuance, TLS deployment, clock quality, owner legitimacy, real vendor integration or model quality. See BUILD-TESTS.md for actual retained runs and failures.
