# Native Finance recipient validation and acceptance

Bounded engineering implementation verified by RUN190/192/193/194/195; see BUILD-TESTS.md for source revisions and actual results. Finance owns incumbent accounting; this evidence workflow never posts, publishes or deploys. AF13 operational acceptance remains distinct from a synthetic/definition scope and requires separately verified native execution evidence.

Configure F01.validation_handoff through the private handoff configuration screen and normal policy lifecycle. Supply exact F01 ValidationPackage IDs, actual recipient and independent acceptor, mandatory independence and an owner-supplied freshness limit. The original Finance owner remains governed by F01.agent_projection. AF13.owner_validation_rules must independently authorise the recipient for meaning/expectations and the acceptor for acceptance; AF13.acceptance_rules supplies permitted levels/independence. Every participant needs actual native Finance/private and handoff/AF13 grants, including every historical source scope. Unset fixture principals/inventory are not defaults.

1. Prepare a source-backed public AF13 package describing the selected F01 scope and independent normal/exception examples. Keep private transaction bodies in the original Finance source interface. The routing policy cannot recursively be a selected package policy dependency.
2. Complete current original Finance read/review and independently reviewed extraction/draft. Through the configured Finance owner, bind that exact approved draft and package using a stable handoff reference. A changed source/target needs an explicit latest predecessor and immutable successor.
3. The configured recipient inspects authorised private evidence and records a distinct receipt acknowledgement. Acknowledgement alone does not validate evidence. Record explicit recipient validation of the exact received source/package context.
4. Complete separate native AF13 meaning, expectations and acceptance reviews. They pin the recipient validation; an old public-only review is not silently carried over after a native binding is added. Existing AF13 scope/level/examples/criteria and independence checks still apply.
5. The configured independent acceptor separately confirms scoped handoff acceptance. Receipt/validation/acceptance can be returned or withdrawn through append-only human decisions. Latest negative decisions never fall back to earlier confirmations. Source, result/draft review, package, policy, principal, historical grant and freshness changes hold current use; authorised historical inspection remains.

Use /cases/<case>/finance/acceptance/ and the linked private Finance and AF13 screens. The local adapter stores exact native packet metadata/hash and never sends a message or calls QuickBooks. Durable local records are human waits/receipts; there is no invented external delivery job. The bounded agent offers preparation and live private investigation, not decision tools. Generic AF13 agents omit native-bound packages, and native decision audit events are private. Definition/synthetic acceptance does not accept the whole product or activate business policy.
