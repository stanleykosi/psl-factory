# Domain policy impact and reviewed reassessment

Guide10 requires policy changes to identify affected work and support versioned reassessment. This workbench implements an engineering review over actual persisted domain policy pins. It does not decide owner policy, appoint business approvers, activate configurations, copy human decisions, restate Finance or dispatch/retry effects.

Open Policy scopes → Domain-specific policy impact and reviewed reassessment. Select an affected executable local Configuration and the currently active, later local Configuration of the same component and case. Reusable scope sources must first be explicitly applied as local configurations. Both source namespaces remain permission checked; a grant on the target alone cannot disclose source records.

Select the declared domain adapters to investigate. Current case/policy access is required, plus each domain's actual read actions. Private response effects reuse the existing native private-response authorization service. The closed registry includes PMO baseline decisions, action states and report schedules; Finance mapping/allocation/formula previews, billing preparations and invoice jobs; BaaS flow events, summary reports and private response jobs. The projection returns IDs, statuses, receipt presence and current heads, never source bodies, money values, payroll/HR inputs or response text.

Live record pages use signed actor/case/configuration/adapter cursors and at most50 records per page. They are live pages, not a stable complete dependency inventory. An immutable assessment includes all observed matches for each selected adapter, up to100 records per adapter. Exceeding that budget holds capture rather than silently truncating it; paged investigation remains available. The interface explicitly reports unknown coverage for unregistered consumers, other indirect dependencies, controlled-document audiences and private Finance/HR/payroll/BU paths. Selecting an empty adapter is not evidence that all product dependencies were found.

Capture stores the exact policy/source states, selected domain records/heads, evidence, reason and canonical digest. Repeated capture of identical inputs is idempotent. Review requires a different active human with current case/policy activation rights and all selected domain/source read permissions. This two-person rule is an engineering integrity control, not a business approver assignment. Acceptance requires the author still has current configuration/read rights, the candidate remains effective and every observed policy/head matches. A changed observation requires a new captured assessment. Reject/defer preserves its own explanation. A recorded review is immutable; reassessment is another observation, not an edit.

Acceptance does not repair the affected domain records. Re-record PMO decisions through PMO services; rebuild Finance previews through Finance services; review current BaaS flow/report work through its source-owned interfaces. Existing decisions retain their original policy foreign keys and cannot authorize a new configuration simply because an engineering assessment was accepted.

Effect states distinguish pending work, potentially uncertain/leased work, persisted committed receipts awaiting reconciliation and confirmed committed effects. A persisted internal receipt is not proof of a customer-channel clock attestation. Recovery continues through the existing receipt-first worker/operator paths. This workbench never retries a job, changes its fence, erases debt or overwrites a receipt. Changed job/receipt heads make the captured assessment stale.

The bounded A04 investigator uses the same authorized metadata projection, identifies uncertain and committed effects and explains stale observations. It has no effect tools or external model-provider call. No raw business text is sent to a provider.

Synthetic PostgreSQL evidence demonstrates implementation behavior. A live pilot still needs real authorized users and selected workflow rules, verified source/integration contracts, deployment controls and staff acceptance. Owner values remain deferred outside the pilot's actual dependent operations.
