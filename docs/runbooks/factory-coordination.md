# Governed work coordination

This is a bounded engineering implementation over PSL's native workflows. It does not configure actual PSL owners, activate a live model, or establish all108 release processes as accepted.

## Configure a work scope

Open an authorised workspace's execution settings, then **Work coordination settings**. Leave undecided values blank. Select either internal workflow rules or a reviewed AI planning service, an already authorised coordinator, a response ceiling and recorded configuration decision. Save, validate and activate separate immutable revisions. Selection never grants permissions.

The execution profile selects the configured coordinator and reserves a shared lifetime allowance. An unreserved profile shows its configured limit separately; retries never reset spent allowance. Reservation limits do not prove paid model usage.

Internal workflow rules select a permitted next step through native deterministic services. A planning service uses the engineering `psl.factory-planner/v1` gateway contract. This is not a vendor API. Its reviewed binding, current health, independent planning canary, assessment, selection and receipt lookup must be available. Deployment owns endpoint and secret-reference registries. Business policy contains no secrets.

Planning sends only permitted activity choices, opaque evidence handles, model/protocol identifiers and bounded request limits. It sends no financial values, source bodies, private identifiers or business tools. A planning-only service contract cannot authorise private evidence extraction. Such extraction requires the existing separate reviewed data-projection contract.

## Decisions and outputs

Agents prepare and investigate within native permissions. Native Finance review remains the human decision. In the accounting line, an unavailable planner holds further agent work while qualified people can review an already prepared exact subject. The current source, Finance rules, role, record grants and subject packet remain enforced. Existing figures and historical receipts remain inspectable.

Agent success, human approval, publication and recipient receipt are different facts. Verification requires the native output and exact downstream receipt. The tested browser line uses synthetic configuration and an internal recipient inbox; it is not a real model evaluation, external delivery, independent UAT or production authorisation.

## Recover an uncertain plan

Use **Check original planning response** on the existing item. It looks up the original operation and stores a typed immutable receipt. It does not send another request or reserve another allowance. A provider not-found result leaves the operation uncertain. Do not create a replacement work item or reset its budget.

Recovered choices are checked against current evidence, policy, permissions and permitted actions before a native command. Changed context retires the old choice. Cancellation retains unresolved effects until evidence is recovered. A stale worker cannot finalise or fail a replacement worker's claim; an authenticated receipt may survive for the current worker to reconcile.

Original invoice and department-request receipt recovery does not depend on planning availability. Original provider binding changes still require fresh reviewed recovery authority; credential/binding rotation remains code work.
