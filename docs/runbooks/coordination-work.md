# Source-owned coordination discovery

`/work/` includes two additional kinds of recorded work. It creates no assignments, approvals, reminders or delivery effects.

Department requests appear only for the actual recipient of an immutable internal routing receipt, with current case/read/receive access, current request, current route/contract acceptance and unchanged sender/recipient authority. A reserved but undelivered request is absent. A successor request or changed authority holds discovery; the original receipt remains intact. Receipt history is deduplicated by request, and reserving another delivery does not itself erase an already delivered current request. Current referenced accepted/rejected/withdrawn decisions remove the item from this work list. Missing source verification remains visible as follow-up, never an approval granted by PSL. Source payloads and external identifiers are excluded from the DTO. The department workbench retains all source-reference and verification decisions.

RFP coordination appears only for the current intake's latest assigned PM, retaining current PM role, prepare permission and assignment-maker authority. A new intake requires its own current assignment. A won/lost disposition removes the coordination item; history remains. The deadline comes directly from intake and keeps unknown/not-stated/stated provenance. Rendering the work list does not calculate a business calendar or authorize submission.

The shared RFP assignment validator is also used by source snapshots, so an inactive assignment principal cannot remain valid by retaining an old in-memory user object. Existing human reviews, internal submission receipts and outcome controls remain separate.

Scan bounds and per-kind limits are engineering bounds, not a claim that all work or SLAs are represented. Current typed P02 route/contract validators and D05 RFP role/action configuration remain the authority interfaces. This increment installs no actual owner, threshold, policy value or provider credential. Authenticated PostgreSQL UI tests use explicitly synthetic people and sources; they do not establish operational acceptance.
