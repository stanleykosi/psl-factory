# Reviewed private evidence gateway

Engineering protocol, not a source-backed vendor API or actual model-quality acceptance.

The case's `/private-evidence/` workbench captures private input, prepares exact source quotations, drafts `INT.agent_data`, records independent projection review, reserves durable extraction, and reviews/corrects returned citations. Configuration lifecycle validation/activation uses the existing policy screens. All source, result and correction responses require current `case.read`, `agent.data.read` and `agent.data.source`; metadata alone does not include source text. Responses are `no-store`. Existing principals receive no automatic grants.

The closed source adapter inventory accepts `plan`, `completion`, and dedicated `agent_private_input` evidence. A dedicated private input is an explicit human-supplied projection, not proof that its author had access to another system. Raw payroll, HR, billing, migration and other restricted domain evidence cannot be selected through this gateway. Additional domain adapters need their own field projections and source-authority checks. Generic evidence/document/extraction readers exclude `agent_private_` evidence.

Before sending, configure exact evidence IDs, original process IDs, purpose, provider contract, actual sender/reviewer and D05 roles, independence, request/input/output/attempt budgets, review lifetime and lease. `tools` must be empty. Null owner values cannot activate; capture remains available. Explicit synthetic fixture values are not production recommendations. No retention duration, real provider, approver or permitted business action is invented.

The selected provider also needs current reviewed readiness, explicit model/credential/target binding and deployment-owned endpoint/secret registry. Readiness's public-canary data scope never authorises private egress by itself. The separate data policy and projection review authorise only the exact extraction operation. Readiness and data policy/authority/source versions are pinned in the immutable job intent and rechecked under case/grant locks immediately before sending. Later source versions, projection versions, reviews, authority changes, policy changes, credential rotations and readiness changes hold that intent; create a newly reviewed intent rather than silently changing the old one.

Run `.venv/Scripts/python manage.py work_private_evidence --case <UUID> --limit 1`. The optional case scope selects work and does not grant authority. Do not drain unrelated demonstration queues. Requests use a stable idempotency key. The engineering gateway implements:

- `POST /extract`: `{model_id, purpose, process_id, data_scope: reviewed_exact_quotes_v1, input: [exact quotes], tools: []}`.
- `GET /extractions/<operation-key>`: the same strict operation-key/status/result receipt envelope used by readiness, in a separate namespace.
- Output: `{facts: [{quote}], uncertainties: [string], proposed_actions: []}`. Only quotes contained within one projected quotation are accepted. Trusted services attach original evidence/version/hash and projection provenance.

Existing bounded authenticated transport enforces deployment-owned origins, HTTPS except explicitly synthetic loopback, no redirects/proxy inheritance, fixed paths, bounded JSON, finite values and duplicate-property rejection. This protocol requires a verified external implementation with durable idempotency/receipt lookup; no vendor capability is assumed.

Jobs use PostgreSQL leases/fences and immutable intents. Existing local receipts reconcile first. Remote receipt lookup sends no new source text and precedes sender/review/budget checks so an accepted request can be recovered after revocation or exhaustion. Binding changes prevent querying a replacement endpoint as though it were the original. Uncertain transport/response errors remain unknown; retry always looks up the original operation first. Held jobs can be retried with the original current intent; cancellation cannot erase uncertainty. A terminal invalid output stores only its hash and an invalid flag, never untrusted invalid text. Valid but unreviewed output is stored only in the private receipt model, not generic AgentRun/evidence/publication records.

Human confirmation/correction creates immutable review history; correction has the same source quotation and output-budget constraints. Confirmation requires current source/provider/data-policy context, configured role and independence. Return/withdraw preserves history. A previously reviewed result becomes unaccepted when its context changes. No review creates an invoice, release, payment, publication or other domain effect. Downstream reuse beyond the protected result interface requires a further explicit integration.

Verification uses real Django services and PostgreSQL with an authenticated loopback mock gateway. This is transport/contract evidence only. Actual provider/model execution, model quality, approved private-data egress, managed authentication/secrets, source-specific adapters, retention implementation, independent security/UAT and owner acceptance remain distinct work.

Generic source consumers also reject agent_private_ evidence through the shared subject resolver. The generic timeline excludes private agent operations and events referencing those private inputs, including their source hashes; audit records themselves remain immutable. JSON missing-key handling preserves unrelated public activity. Non-finite values, malformed UTF-8 and malformed transport structure remain unknown and lookup-first rather than creating an invalid local success or allowing an untracked resend. Browser verification confirms metadata-only access and protected result403 for the read-only synthetic viewer.
