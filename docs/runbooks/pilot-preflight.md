# Selected read-only pilot preflight

Engineering interface, not a live pilot receipt or source-backed business policy.

Open the case's Policy impact page, then **Read-only pilot preflight**. Current case.read, policy.read and pilot.read grants are required before any selected record lookup. pilot.configure permits saving a contract version; pilot.capture permits saving an observation; agent.pilot permits the bounded native investigator. These technical grants neither appoint business approvers nor establish domain action authority.

Select the original process IDs, registered operation IDs, actual case participants and exact action keys to check. Select existing integration contract IDs and family:id jobs explicitly. One contract covers one case; cross-case campaigns require separate records. The form's action selection applies to every selected participant. The service also supports an explicit per-participant action list. A declared process/operation association is a rehearsal boundary, not a verified mapping from source responsibilities to runtime authority.

An integration selection requires current integration/source read plus native private/source permissions. Selected jobs require ops.read and native family/job permissions; selected protection proof/artifact metadata requires the corresponding read actions. Missing private permissions deny the projection instead of exporting a partial private packet. Only permission-checked IDs, hashes, statuses and observed heads are exported. Endpoint URLs, credentials, source bodies, amounts, provider messages and private payloads are excluded.

Save the contract, inspect its current projection and capture an evidence pack. Contract versions use an explicit predecessor. PostgreSQL append-only/identity guards protect contracts and observations. Duplicate captures serialize on the case and reuse a still-fresh matching observation; an expired matching observation can acquire a fresh successor. Packs expire after 15 minutes, an engineering observation bound, not an owner deadline or business retention rule.

Interpret the evidence in separate groups:

- **Software/coverage:** selected IDs and operation dependency registry only. Unknown variants, unselected families and operation-to-participant action sufficiency remain explicit. This is not all-122 acceptance.
- **Technical:** source fingerprint of the current preflight process, actual database endpoint identity hash, applied migration identity, pending migrations, DEBUG status and Django security check IDs/levels. No settings or diagnostic text is exported. Actual worker identity, storage/retention/monitoring and SSO/Security/load/UAT are unverified.
- **Owner policy and identity:** each selected operation independently resolves only its registered dependencies. Missing/expired/revoked/invalid rules hold that dependent runtime transition. Current participant active state and selected exact case/action grants are recorded. The preflight neither installs values nor executes domain runtime guards.
- **Integrations:** current native readiness assessment/review, authenticated-probe and observation heads, selection head, contract and deployment credential-revision hashes. Local/internal receipt readiness is not external customer delivery, real-model evaluation or operational acceptance. No provider probe or network request is made by this preflight.
- **Recovery:** selected job state/fence/attempt/lease, local handoff/invoice/publication receipt checks and authorized protection artifact/proof hashes. Other receipt variants remain unverified. A supplied recovery proof does not establish actual native restoration. Uncertain/leased work requires receipt-first source-owned investigation; no retry or restore tool is available.
- **Human verdict:** no supervised run has occurred merely because this pack exists. Record actual staff/owner/provider/oracle/UAT evidence through the relevant domain interfaces and supervised runbook. Operational acceptance remains false.

Detail and JSON download reproject current native access before releasing stored metadata. Changed case/policy/source/grant/build/migration/integration/receipt/job heads, contract successors, author authority loss or expiry make the recorded observation stale. Losing private source access denies reading historical metadata too. No stored actor, model result or restored archive grants fresh authority.

Use `docs/runbooks/supervised-impact-pilot.md` for the human operating sequence. Supply only the actual policies required by the selected runtime path later; unrelated owner slots remain deferred. Keep outbound work held until its actual destination contract, authority and receipt semantics are established.
