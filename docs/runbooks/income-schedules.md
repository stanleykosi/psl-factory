# Income detail and schedule validation

Source-backed scope: F12 describes finer manual income detail. A manual amount may disaggregate existing income, reclassify it, or be an independently justified addition. A selected observed workbook expression multiplies a linked note by1000; it is evidence of one expression, not a universal conversion rule. F13 names management-account schedules without supplying their complete formulas, intercompany rules, equity controls or actual owner appointments. Whether monthly performance is a separate output remains unresolved.

## Connected local path

Open `/cases/<case-id>/finance/schedules/` with explicit case.read, finance.read and schedules.read grants. Prepare and review commands additionally require their exact grants. The board displays controlled Finance working amounts; this is not a public or payroll metadata board. Responses and reviewed JSON reports use no-store. The action forms are CSRF protected and reject extra authority fields. Configuration uses the existing draft -> validate -> activate lifecycle and immutable registered references.

Configure F12.detail_rules for one exact entity/period/currency/report line, source and target units, explicit positive factor, permitted relationship types, source-overlap handling, child tolerance and known/unknown conversion oracles. A policy may hold all overlapping supplements or allow explicit evidenced resolution followed by human review. The engineering interface supports an existing current Finance mapping note as its parent. Existing source acceptance, mapping/configuration reviews and source-control checks must be certifiable. Parent signed amounts remain signed; no inferred display-sign reversal. Conversion applies once to the parent; each manual amount already uses the target unit. Unconfigured rules allow a held register to be captured while independent inventory work continues.

Disaggregation children reconcile to the converted parent and never add to it. Reclassification rows must net to zero. Additive rows change the explained total only after explicit separately-justified classification. Unknown amounts, child residuals outside configured tolerance, unassessed/already represented supplements, repeated manual source accounts and unresolved source-account overlap hold approval. Overlap requires an explicit resolution evidence reference and the exact human work review. These checks assist review; supplied references are not proof of native source coverage.

SCHEDULES.review_authority nominates actual active Finance principals by income/inventory purpose and explicitly selects reviewer independence. D05 actual Finance role assignment and action grants remain necessary. An approval binds the precise work version, sources, policy and AF13 acceptance state. Source, policy, owner review or access changes require a rebuilt successor. Returned/rejected/revoked decisions remain immutable history.

Exporting an additive/reclassification into the existing Finance reporting-adjustment service is separate from reviewing an explanation. Every exported row needs exact source-unit account lines reconciling to its amount. Converted target-unit adjustments are held at export until a separately reviewed source-unit proposal exists; their valid explanation remains usable. Disaggregation cannot export. Corrected work under the same reference creates a successor of the same adjustment reference, preventing selection of both revisions. Reusing the same manual evidence/key under another exported reference is held for reconciliation. Each export still requires the existing Finance adjustment approval and explicit selection in a new mapping. Nothing posts a journal, edits QuickBooks, issues an invoice or allocates cash.

## Schedule inventory and AF13

Capture bounded schedule_inventory JSON evidence using the shape in fixtures/schedules.json. Duplicate JSON fields, nonfinite values and extra authority fields are rejected. Each supplied schedule records its purpose, actual owner reference, dependencies, source/formula/manual-cell evidence, consumers, restriction marker, explicit gaps and AF13 validation package. Missing workbook evidence and absent formulas/owners/examples remain explicit exclusions; a named tab never becomes an executable accounting definition.

Configure F13.inventory_rules with actual required schedule keys, accepted evidence levels and the monthly-performance decision. No schedule list or monthly-output decision is supplied by default. A decided monthly-output relationship needs scoped decision evidence. Required-schedule omissions, partial coverage and undecided monthly reporting remain visible even when Finance reviews the bounded inventory as a useful exclusion register.

For inclusion, the exact AF13 package reference must equal the schedule key, so acceptance cannot be reused for another schedule. It must cover F13, have current actual-owner meaning review, normal and exception expectations, and accepted definition or synthetic implementation evidence. The meaning-review principal must equal the declared schedule owner. The package must bind all schedule source/formula/manual evidence and the supplied workbook reference. Existing AF13 owner authority, review independence and acceptance safeguards apply. Definition acceptance is distinct from executing a formula; supplied comparisons are distinct from actual native execution. Operational acceptance remains unavailable in the existing AF13 service until verified native execution adapters exist.

Dependencies must be acyclic. A missing or excluded upstream excludes its consumers. An otherwise accepted equity definition can be included while an unverified intercompany schedule remains excluded. `complete_inventory` means the explicitly declared local inventory has no recorded completeness gaps; `native_workbook_verified` remains false. No full-product or native workbook certification follows.

## Agents and adapters

The bounded deterministic investigator selects status/gap projections for at most40 versions, cites IDs/hashes/parents and drafts owner questions. It reads no numerical income fields, does not grant authority and makes no provider-evaluation claim. The supplied adapter validates a local JSON inventory; it does not parse or recalculate Excel. The local reviewed-report adapter rechecks current exact work, human decision and grants under case/grant locks. There is no remote write or uncertain external effect to retry.
