# F01 private Finance evidence

Engineering design. Finance retains incumbent QuickBooks posting and its independent original verification review. This path creates private selected-field evidence and human-owned unsent drafts; it never posts, changes treatment, resolves a conflict, approves funds, publishes or grants AF13 owner acceptance.

Configure F01.agent_projection through the existing typed ledger-policy editor and policy lifecycle. Supply exact case lineage IDs, selected closed fields, purpose, actual scoped Finance/D05 projector/owner/independent reviewer, draft size and review lifetime. The fixture has unset people and no source inventory; its synthetic budgets are examples only. Missing native policy holds projection/reuse, while original capture/verification/review and configuration remain available. INT.agent_data independently governs exact evidence/process/purpose/provider, sender/reviewer and input/output/request/attempt/lease budgets.

1. Complete original incumbent verification and independent Finance review. Where a duplicate/reference conflict exists, complete its exact resolution packet and fresh post-decision verification/review first. Unknown, ambiguous, expired or unreviewed sources cannot be projected.
2. In Private Finance projections and drafts, select an explicitly configured source and stable key. Only configured string fields are copied; evidence bodies, resolution reasons, treatment bodies, credentials and arbitrary source references are not fetched or disclosed. A native immutable binding pins the exact original report, check/review/resolution snapshot, policies, owner and historical participant scopes.
3. Independently review the exact projection through the shared private extraction workbench. Configure/select a verified provider capability contract and the INT.agent_data egress rule. The native Finance reviewer and independence checks apply even if the generic gateway policy's optional independence is false.
4. Reserve extraction and run only the case-scoped private evidence worker. It sends exact reviewed quotations through the authenticated fixed-origin adapter. Tool/action proposals and uncited facts are rejected. Unknown responses reconcile by the original operation key before any retry. Receipt recovery may reconcile a committed result after source revocation, but revocation prevents a new send or cached read.
5. Independently confirm/correct the extraction result with exact quotations. The Finance owner can prepare a draft from that reviewed result, make explicit immutable human revisions and request a separate independent draft review. Native result and draft review lifetimes are enforced.
6. Historical draft inspection remains visibly separate from the current-approved evidence endpoint. Only the configured Finance owner with ledger.agent.reuse can obtain the latter. It checks current source, policy, provider, extraction review, owner, exact latest draft and independent review. The returned private packet can support a separate controlled Finance/AF13 workflow; it is not an owner acceptance, publication or accounting authority.

Every read/reuse checks actual Finance/private source grants. Historical cross-case participant scopes remain protected even after a newer resolution or loss of current eligibility. Shared gateway lists/forms/results and direct projection reads apply native source access; generic evidence/timelines/agents/export bundles omit raw ledger and private projection bodies. Ordered participant locks and global principal ordering apply before gateway worker sends and current use. SQL guards protect native binding and exact draft/source/result/predecessor lineage.

A current original Finance read/review change, pending conflict successor, policy/role/grant change, provider/readiness change or withdrawn/expired review requires a new explicitly reviewed projection/result/draft as appropriate. Do not overwrite historical sources or refresh old examples to satisfy an audit. Loopback provider tests prove gateway behavior only; real-provider/native QuickBooks and operational owner acceptance remain separate evidence.


## Private operator recovery and metadata readiness

Engineering interface `ledgerdata` is limited to F01 extraction jobs with an actual native Finance projection binding. Generic and Support extractions cannot be relabelled into this family. The shared operations screen supplies inventory, configured recovery and metadata export/backup/isolated restore; the integration screen supplies versioned contracts and human readiness reviews. The Finance screen links both and shows live source-authorised operator guidance without writing generic AgentRun output.

Configure an explicit OPS.operator_rules route `{family: ledgerdata, actions: [retry]}` with actual Finance/D05 operators and native source/read/agent.data.operate grants. Existing configurations do not acquire this permission automatically. A retry requires held work, no committed receipt, unchanged original sender/context and remaining original attempts. Unknown outcomes are reconciled by the original case-scoped extraction worker, never cancelled, rekeyed or reset. A changed context needs a new explicitly reviewed extraction intent; the old history remains.

OPS.protection_rules governs record budget, sealed metadata storage and isolated metadata target. RPO/RTO remain explicit unknowns until an owner supplies them. Exports contain only safe public evidence hashes and job IDs/status/fence/attempt/lease metadata, with no private quotations, incumbent references, draft bodies, credentials or job intents. Backup and isolated PostgreSQL restore preserve this metadata and never recreate/replay extraction jobs or accounting effects. Source access, including every historical Finance participant scope of each referenced job, is checked again for cached inventories, manifests, artifacts and protection reports. Revocation hides cached UI rows and denies direct access.

Optionally enrol a separate `ledgerdata` adapter contract using internal_postgres_session_v1 / internal:ledgerdata / runtime:postgres / psl.internal-receipts/v1. Probe actual database session privileges and exact local extraction receipt existence, independently review the readiness assessment, and keep provider readiness separately configured. A local receipt lookup never contacts the private provider and does not prove QuickBooks authenticity, reviewed output, a new private send or owner acceptance. Enrolment holds new sends while readiness is absent/stale/revoked. Worker receipt reconciliation precedes this gate, so an uncertain already-committed provider result is recovered once even after source or readiness revocation.
