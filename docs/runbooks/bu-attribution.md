# Exceptional staff allocations and transaction BU references

Source-backed scope: F21 describes individual formulas for some staff, but supplies neither confidential percentages nor actual approval authority. Exact restricted F16/F17 subjects/components, F20 pool exclusion and F23 conservation must refer to the same source population. F44 describes a proposed future event-level BU reference/report, not an existing ledger implementation or posting-authority change.

## Staff-cost path

Use a current independently reviewed F17 payroll match and its exact F35 HR authorisation/receipt. Configure F21.allocation_rules with entity/effective periods, eligible components, same standard-pool reference and contract evidence, standard matched-BU or explicit fixed weights, rounding/residual treatment and historical handling. Five supplemental BU interfaces are engineering configuration, never operational defaults. Private individual rule rows contain exact employee/component/period, BU weights, pool-exclusion reference and safe rationale evidence ID. Do not put employee IDs, private ratios or payroll amounts in shared evidence or policy artifacts.

A configured Finance human reviews the exact private rule against the source population. Declare the private exception pairs when preparing the staff population: each pair needs exactly one current reviewed rule. The complete latest eligible-component private exception inventory is pinned at preparation. Known pending/returned/approved classifications cannot be omitted into standard treatment; only an explicit configured human revocation withdraws an exception. Later classification/rule/review changes invalidate prior output and require reassessment. Legacy immutable work reconstructs its original ID/review inventory from creation-time history without rewriting data. All other eligible rows use the configured standard method. The same calculation excludes exceptions from that standard pool and reconciles source, allocated totals and residuals. Unknown amounts, missing ratios, duplicate declarations, unknown BUs and residual holds block approval. Never infer an executive rule from job title or reuse the prior month. This bounded protocol uses one exact payroll population; external incumbent-pool authenticity and broader schemas require separate verified adapters.

## Event path

Configure F44.source_rules with the approved design-decision/source-contract evidence, actual Finance source owner/readers, source namespace/entity/period/currency, freshness/retained access, closed-period policy and comparison mode. Capture a bounded supplied full-population JSON export. Extra fields, duplicate IDs, wrong scope and stale extracts retain only sanitised codes/hash. An authoritative tenant/source/event claim prevents another case or batch reference from counting the same event. Supplied snapshots can correct the same reference and preserve prior versions; these claims prove local uniqueness, not native authenticity.

Configure F44.attribution_rules and the effective existing D10 BU catalogue. A single exact direct tag allocates once; an explicit shared tag uses its pool/weights; company-only stays separate. Unknown/conflicting tags stay unallocated and prevent approval, rather than assigning multiple copies to BUs. Totals reconcile to the declared supplied-population control. Report coverage is explicitly selected_supplied_population_only; this cannot establish full-company/native coverage. Supplied signed amounts are preserved; Finance comparisons use the signed source metric, not a display formula or an implicit sign reversal. When configured, supply an exact same-case/current Finance allocation run and metric; the service checks scope/current snapshot and compares the actual conservation source total. A partial/mismatched inventory cannot be published as reconciled. Source/Finance metric coverage must be meaningful and owner-validated before operational use.

Closed periods remain held or require explicitly configured reviewed-reference-only handling. Changed sources/rules create successors. Previously reported periods additionally require a separately configured historical review; prospective-only policy prevents rework. None of these controls reopens a ledger period or silently restates Finance history. F27 native taxonomy/restatement and upstream source changes remain separate authority.

## Reviews, disclosure and receipts

BU.review_authority nominates actual current Finance humans by purpose, with optional independent review. Source/rule/output and any historical decision are exact version/hash bound; publication is a separate permitted command. BU.disclosure_rules defines actual aggregate recipients, destination and minimum staff count. Any protected staff group holds the whole report, including company totals. General recipients see approved BU/company/residual totals only, no staff/event rows, private ratios or counts. Receipt acknowledges the exact local aggregate. The report adapter is read-only and has no remote delivery or uncertain external effect.

Metadata boards, form choices and deterministic agents defer private JSON. Private inspection requires exact current reader/role/case/action checks, including current F35 HR scope for staff joins, plus freshness and retained access. No-store responses prevent application caching. Safe metadata and references can support investigation while dependent financial rules are unavailable. The bounded agent cites hashes/IDs/holds, drafts questions and never reads private values or approves/publishes/writes HR/ledger/payroll.

## Remaining acceptance

Actual exception ratios/oracles/appointments, approved source namespace/design and attribution policy, real source authenticity/coverage, native accounting/HR adapters, remote reporting, provider evaluation, operational UAT, physical purge and encryption/key management remain distinct gaps. Restrict-after-expiry denies access/use; append-only storage is not physical deletion. All demonstrated numeric fixtures are explicitly synthetic.
