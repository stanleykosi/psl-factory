# Private Finance and controlled-document policy impact

Engineering design/implementation. This does not define business values or grant approvals. Test and deployment status is in BUILD-STATE.md and BUILD-TESTS.md.

The case policy-impact workbench selects an affected local configuration, its active reviewed successor, exact declared adapters and policy-decision evidence. A second authorized person may accept, reject or defer the captured engineering assessment. Acceptance records an observation; use the native domain workspace for business decisions, new calculations, disclosures, publications and receipt-first recovery.

Six adapters extend the original ten:

| Adapter | Declared pins | Native metadata permission boundary |
| --- | --- | --- |
| documents.publication_effects | Reservation policies and review authority | Document read plus accepted/private Finance source access where bound |
| finance.ledger_projections | Projection rule and projector/owner authority | Native F01 source and every historical participant case |
| finance.ledger_drafts | Draft/owner rule and source projection rule | Same native projection/participant permissions |
| finance.hr_disclosures | Disclosure contract policy IDs | Existing HR/Finance metadata workbench permission |
| finance.payroll_work | Working-version rules and linked HR contract rules | Existing payroll metadata workbench permission |
| finance.bu_work | BU working rules and linked payroll rules | Existing BU metadata workbench permission |

Payload, amounts, employee identifiers, provider output, document titles and source bodies are excluded. HR/payroll/BU payload access remains subject to its separate current nomination, consent, retention and source checks. The assessment never extends those rights. F01 projections/drafts retain participant-source checks even after a policy changes. An unauthorized selected or lookahead row denies the request before returning metadata, counts or cursors.

Publication receipt lookup checks the exact complete recipient population and projected payload. Partial/mismatched receipts are reconciliation conflicts, not a committed publication. Pending/uncertain work and proven historical receipts remain distinct. Capture/review uses NOWAIT for publication job contention; refresh after native worker reconciliation. No retry or release action is available here.

Current source heads, reviews, policies and authority are read again on review/export/agent inspection. A later working version or revoked grant invalidates current use without rewriting the captured history. Paged investigation has a declared technical budget; it never silently represents a truncated snapshot as complete.

Other consumers and indirect pins remain explicitly unknown unless a typed adapter declares them. This registry is a bounded engineering dependency view, not a claim that every process or effect has been accepted. External business oracles, operational identities and live integration evidence remain separate.
