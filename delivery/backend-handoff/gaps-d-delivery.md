# Board-vs-contract gaps: delivery group (SCR-33, SCR-43 to SCR-49)

Checked 15 Nov 2026 against the approved main-canvas boards (desktop and mobile, every state), `architecture/packages/v7` (openapi.json, endpoints.csv, model.json, delivery.md), the F-17 workspace frame (`frontend/src/features/workspace/`, `delivery/features/F-17/spec.md`) and the line maps `LINE-delivery-*-desktop` (board text only; no code was changed).

Facts that apply to every screen below, stated once:
- SCR-44 to SCR-49 are line workspaces on E-WORK-ITEM (`GET /api/v1/work/{work_id}`, `workspace` block). Steps go through E-WORK-STEP (`POST /api/v1/work/{work_id}/steps`); a step with `task_id` is a human decision (E-TASK-CLAIM / E-TASK-DECIDE); recorded outside responses go through E-RESPONSE; uncertain effects go through E-WORK-ACTION `reconcile`. All of it is `proposed` under D-LINE-WORKSPACE.
- Writes always carry CSRF (shared client); E-WORK-STEP, E-RESPONSE, E-TASK-DECIDE and E-WORK-ACTION carry `expected_revision`; E-WORK-STEP also `idempotency_key`; E-TASK-CLAIM is the claim guard. Proof files go first through E-EVIDENCE-UPLOAD (`POST /api/v1/cases/{case_id}/evidence`, returns `evidence_id`, `case_revision`).
- The six delivery lines have no entry in E-LINES (`start_via` is only `work_start` | `finance_import`). The line maps say each line "starts from" the previous screen, i.e. the factory opens the next work item on a verified output. v7 does not describe that hand-off (see G-43-6).
- Policy values these screens depend on exist only as Setup rule rows (E-SETUP-RULES, component names from `frontend/mock/fixtures/setup/delivery.desktop.json`), all "Not set" except the archive rule: `delivery.hypercare_window`, `delivery.hypercare_criteria`, `delivery.closure_finance_confirmer`, `delivery.handover_review` (not set), `delivery.archive_storage` (set: keep, never purge). None has a D-id in model.json; none of their values is invented here.
- Line keys: the backend today uses `delivery-release/v1`, `delivery-go-live/v1`, `delivery-hypercare/v1`, `delivery-archive/v1`, `delivery-handover/v1`, `delivery-closure/v1` (counted in `apps/`); v7 line keys are underscore style (`weekly_report`, `issue_followup`). Below, the key is written `delivery_release` etc.; the backend developer picks the spelling and the mock follows.
