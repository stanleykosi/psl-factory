Scope: SCR-53 Management accounts (22 boards), SCR-54 Income detail and schedules (14), SCR-55 Fixed asset (PPE) schedule (14), SCR-56 Cash forecast and actuals (14), SCR-57 Business-unit totals (14), SCR-58 Ledger source reference (12). 90 boards, all on the Finance and Payroll canvas (`design/canvas/finance/project/`), all not yet built. I read every desktop board of every state; mobile boards were diffed against desktop and only differ in layout and short wording ("STATION n OF m" line, "← My work", shortened labels), not in data or controls. Read-only work; nothing else was edited.

Sources used: `architecture/packages/v7/` (`openapi.json`, `endpoints.csv`, `model.json`, `delivery.md`), `design/screens.md`, `delivery/screen-coverage.md`, `delivery/features/F-17/spec.md`, `delivery/features/F-19`/`F-21` "Conflicts", `frontend/src/features/workspace/`, `frontend/src/features/start-work/IntakeField.tsx`, `frontend/src/features/finance/month-end/`, `frontend/mock/fixtures/E-MONTH-END.json`, SCR-04 and SCR-13 finance boards.

## How these six screens are carried today (read once)

v7 has **no endpoint of its own** for any of these screens (`endpoints.csv` has E-MONTH-END, E-IMPORT, E-PAYROLL-MATCH, E-INVOICES, E-RECEIPT for Finance, nothing for accounts, schedules, PPE, forecast, BU totals or ledger sources). D-LINE-WORKSPACE (proposed) names them: "design/canvas/finance/project/SCR-53..SCR-59 (quarantine findings, review results, schedules by class with Unknown, recipients and receipts)". So each screen is a **work item page**: `GET /api/v1/work/{work_id}` (E-WORK-ITEM) with the `workspace` block (`line_key`, `screen`, `view`, `status`, `sections[]`, `steps[]`), reached from the month-end list row (`E-MONTH-END tasks[].work_id`, fixtures W-1602 to W-1606), plus the existing `stations`, `agent`, `tasks[].decision`, `reconcile`, `allowed_actions`.

Proposed line keys (not in v7; the backend chooses): `management_accounts`, `income_schedules`, `fixed_assets`, `cash_forecast`, `bu_totals`, `ledger_sources`. `workspace.screen` = "SCR-53".."SCR-58"; `workspace.view` = the board state name (quarantined, units, investigating, reviews, ...). Header reference (ACC-0010, SCH-0021, PPE-0006, FC-0014, BU-0031, LED-0052) = `item.reference`; crumb "FINANCE / MONTH-END / ..." = `workspace.context.crumbs`; "SAMPLE DATA" = `item.sample`; the coloured state chip = `workspace.status {label, tone}`; the station track = `stations[]`; "Chidi investigating ... step 3 of 4, Started 13 Nov 09:02" = `item.agent {name, status, steps[{text,status,source,at}], started_at}`; "Next" = `workspace.next[]` / `item.next_step`.

Month-end (SCR-36, built) fields to reuse in the line pages: period naming and `parsePeriod`/`periodNames`, `asOfLine` (`coverage` + `as_of` as "FROM RECORDS YOU CAN SEE · UPDATED 10:42"), `compactAmount` for "₦12.4M" next to full "₦12,400,000.00" via `formatAmount`, `UNKNOWN`, `STATE_TAGS`, `tone`/`status_label`, the restricted row ("HR only"). SCR-36's `tasks[].work_id` is the entry point; its `next_action {label, work_id}` is the model for the link gap G-C-3.

### Shared patterns (noted once; screens refer to them as SP-n)

- **SP-1 Investigating (Chidi).** Boards `*-investigating` (all six screens). A facts/figures section of what was read, `item.agent.steps` with `source` ("TB_OCT.CSV · 412 ROWS · CONTROL TOTAL MATCHES") and `started_at`, `agent_note`. Fully covered by `item.agent` and `facts`/`figures` sections, except "Ask Chidi" (G-C-4). The agent only reads and drafts; the person decision that follows is named per screen.
- **SP-2 Decide panel** ("Decide · Finance reviewer", note "needed to return, reject or withdraw", Approve / Return with a note / Reject, sometimes "Withdraw approval"). Carried by `tasks[]` with `decision` (version, basis, prepared_by, chain), `required_role`, `you_can_act`, `cannot_act_reason` (prepared_by_you gives "A reviewer can't review a part they prepared"), claim by E-TASK-CLAIM, verdict by E-TASK-DECIDE (`verdict` approve|return|reject|revoke, `note` <= 2000 required to return/reject/revoke, `expected_revision`). Gaps G-C-1 and G-C-2.
- **SP-3 Returned / rejected / withdrawn, "Correct and resubmit"** (53 returned, 54 returned, 54 withdrawn, 55 returned, 58 rejected). The reason quote is carried by a `timeline` section item; "What happens" rows by `facts` with status; the correction by a workspace step with fields. Gated by **D-RETURN** (open: "every return creates a correct and resubmit task for the preparer. Today accounts, the shared engine and schedules differ"). The board itself says "Proposal: every return gives the preparer this task. Today the backend only waits (question for backend)". Gap G-C-6 for the new run.
- **SP-4 Delivery uncertain / reconcile** (53 uncertain, 56 uncertain). Covered by `state: effect_uncertain`, `reconcile {what, sent_at, checks{count,first_at,last_at}, outcomes, resend, unknown_note}`, `allowed_actions` (reconcile, cancel), E-WORK-ACTION (`action`, `outcome`, `evidence_id`, `expected_revision`). INV-RESEND honoured by the contract. Gap G-C-5 (per recipient) and G-C-7 (what is sent).
- **SP-5 Recipients and receipts** (53 publishing, 56, 57). `recipients` section (name, `channel`, `receipt` received|not_yet|uncertain|failed|unknown, `at`) covers the table. Receipt `uncertain` and `unknown` must never read as received (already frontend-owned). Gaps G-C-7, G-C-8.
- **SP-6 Held / Setup needed** (53 setup-needed, 57 held, 56 group-review). `state: setup_needed` or `owner_needed`, status chip, `facts` with "NOT SET" tags. Values come from Setup · Finance rules (SCR-13 finance-rules board lists all 25 as NOT SET, e.g. "Statement contract", "BU metrics", "Finance executor (who publishes)", "Group reviewer", "Disclosure rules and recipients", "Conflict rules", "Who reviews ledger sources"). None of these has a decision id in model.json; they are Setup rule values (E-SETUP-RULES, D-SETUP-RULES-VIEW). Never invent them; the dependent runtime transition holds (AGENTS.md). Link gap G-C-3.
- **SP-7 Verified** (all six). `facts` with explicit negatives ("Posted to the ledger NO", "Authenticity certified NO", "Changing the source file NEVER"). Covered by `facts` (value "No"/"Never" is backend-supplied text). Nothing is posted by any of these lines; this must be a backend guarantee, not copy.
- **SP-8 Money.** Every amount is `money {amount, currency, unknown}`; Unknown is the word, never 0 (INV-UNKNOWN). Boards that touch it: 53 control total/results, 55 Furniture, 56 January and Payroll actual, 57 staff cost.
- **SP-9 Agents never grant authority.** Chidi's output never approves, publishes or pays (INV-AGENT; E-WORK-STEP rejects agents on approve/send/pay steps). Three boards add a data limit the backend must enforce: PPE "Chidi never reads asset values; he checks structure, dates and provenance" (SCR-55), BU totals "counts only, never individual pay" (SCR-57), and "Chidi doesn't see the values" while calculating (SCR-55). I-AGENT says "payroll private rows never leave HR scope"; it does not say asset values stay out of Chidi's context.
