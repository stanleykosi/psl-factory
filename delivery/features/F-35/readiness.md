## Binding rules for the spec
1. **No invented authority or recipients.** The reviewer, audience and "Tuesday skips review" are shown only as returned text, `recipients` and `steps`. The frontend has no rule about which reports need review. Decide controls appear only when `you_can_act` is true. One fixture has the reviewer not set: a `setup_needed` / held status, no actionable task, no controls.
2. **Access (INV-ACCESS).** Coverage and "left out" are rendered from the backend's text and counts. The frontend never names, lists or infers projects the viewer cannot see. Hidden or unknown is never 0. The board's "named as left out" sentence shows only as returned text.
3. **Sends.** "Approve and send" never shows "sent" or "received" from the click. A timeout or 5xx re-reads the item. There is no automatic or offered resend while any receipt is `uncertain` (INV-RESEND). The header and status come from the backend. CSRF, `expected_revision`, `idempotency_key`, and claim before decide all apply.
4. **Agent work is not an output.** Tola's checklist and counts are agent work as returned. "Verified" and "received by every recipient" appear only from backend state and receipts.
5. **Design.** Tokens and shared components; labels, announced errors, reduced motion; 44px phone targets (D-92c, D-95). The phone review's missing note and Return follow the F-29 precedent (full-height Drawer) as a listed conflict. Fidelity per D-64/D-83: one run per round over the 8 boards, 100% coverage after exceptions, visual of at least 70 with signed per-board waivers. Axe at 390 and 1440.
6. **Tests.** Fixtures for drafting, review (can act), review (`prepared_by_you`), review (reviewer not set), returned-to-draft re-read, tuesday (one uncertain), received, and a 409/uncertain decision. Unit tests plus Playwright with a request log: no return without a note, no write when the person cannot act, one write per click, a re-read after an uncertain failure, and no resend control while uncertain.
