## Binding rules for the spec
1. **Money (INV-UNKNOWN, AGENTS.md).** Every amount is the backend's decimal string with its currency, formatted by the shared formatter with no float conversion. `unknown` or a missing amount shows "Unknown", never 0, blank or a dash. The frontend computes no total, count, "2 OF 2", row split or result. Each of these is backend text or a backend number shown as sent.
2. **Agent work is not a decision (INV-AGENT).** Chidi's steps, sources and "CHIDI CHECKING" render as agent work. "Possible duplicates" is never shown as "no duplicates" when it has not been assessed. "Verified" appears only from `state: verified`, never from an approve click or an agent claim.
3. **Separation of duties stays with the backend.** The decide controls show only when `tasks[].you_can_act` is true. "You didn't prepare it" and every refusal come from `cannot_act_reason` (`prepared_by_you` → the existing `cannotActCopy`). The frontend has no role or person rule. 403 and 404 look the same.
4. **Policy not set means held, never guessed (guide/10).** No fixture names a real approver. The review fixture is marked `sample` (synthetic-active). Add one fixture in which "Who reviews schedules" is not set: the backend returns `setup_needed` or `owner_needed` with its status and facts, no task the person can act on, and no decide controls. The page shows exactly that and invents no reviewer. This proves the narrow runtime hold.
5. **Writes.** Claim first when the task needs it (as `useDecision` does). Send `expected_revision` as read. Return and reject need a non-empty note of at most `NOTE_MAX` characters, with an inline, announced error. The correction step sends an `idempotency_key`. On a timeout, network failure or 5xx, re-read the item before offering a retry, never show "approved" or "resubmitted" from the click, and never resend automatically. A 409 means re-read and the stale message.
6. **Verified negatives are backend facts.** "Posted to the ledger NO" and "THESE 38 ROWS ONLY" render from `facts` as sent. They are not frontend copy, and nothing in this feature posts or exports.
7. **Shared library and tokens (D-91 to D-93).** Labels on every field, errors announced, reduced motion respected (agent pulse). Phones get 44px targets (D-92c), and links inside sentences are exempt (D-95).
8. **Fidelity (D-64, D-83).** One design-fidelity run per round over the 8 boards. This is a line screen, so D-83 applies: 100% coverage after exceptions, no fixable gap in the UI reviewer's side-by-side reading, and visual of at least 70, with a per-board waiver signed in fidelity-exceptions.json citing D-83. Axe at 390 and 1440. Sonnet builder only if the coordinator accepts the risk. This is high risk, so D-64 allows Opus.
9. **Tests.** v7-typed fixtures for investigating, review (can act), review (cannot act, `prepared_by_you`), review (reviewer not set), returned, verified, and an Unknown amount. Unit tests plus Playwright with a request log proving: no decision is sent without a note on return or reject; no write happens when the person cannot act; one write per click with the same idempotency key on retry; and the re-read after an uncertain failure. The existing response and month-end tests keep passing.

## Risk
High, because this is a Finance approval over money. A reviewer approves the October income detail (₦12,400,000.00 service revenue), and a wrong control would let a Finance figure look approved or verified without the human decision. The rules the product forbids most are at stake here: unknown shown as zero, a frontend-computed figure, an invented approver, an agent claim read as verified. The work is contained: a view on the F-17 frame with the existing E-TASK-DECIDE and E-WORK-STEP writes, on the mock, with nothing posted.
