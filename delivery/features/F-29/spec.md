## Summary
- A new page `/projects/[caseId]/documents/[documentId]?v=<version>` shows one drafted client document: numbered plain-text sections, the changed-section marker, the agent notes, the Checks panel and the audience, inside the F-25 project frame.
- A person who may act on the review (backend `you_can_act`) can approve it or return it with a note, with the existing claim and decide writes. Everyone else sees why they cannot, in plain words.
- A returned document shows who returned it, when and the quoted note (only where the backend sends it), and says approval on that version is not carried over.
- A minimal read-only Documents tab (item 2) lists the project's documents and links each to this page.
- Mock only: the backend fields are contract proposals; drafting or editing a next version is not available (item 1); approving never claims the document was sent to the client.

### Reads
- **E-DOCUMENT** `GET /api/v1/documents/{document_id}/versions/{version}` (existing fields: `document_id, version, title, status, template, body_url, test_template`). Proposed additive fields, in `frontend/mock/proposals/document-review.json`:
  - `case_id`, `project_title`, `reference` (G-SCR08-6): crumb "LAGOON HEALTH / DOCUMENTS / SOW-0198" and the project tab bar. Without `case_id` the page cannot find its project: shows the read-only document with no tab bar, no crumb link.
  - `sections[]` `{key, heading, text, changed_since?: boolean, notes?: [{agent, text, cites?: [{label, reference}]}]}` (G-SCR08-1, -2). `text` is plain text (paragraphs split on blank lines), never HTML. `notes` are agent text only.
  - `checks[]` `{key, label, status: done|held|blocked|unknown, detail?, cite?}` (G-SCR08-3), computed by the backend. Rendered in the order sent, status words Done, Held, Blocked, Unknown. No check is computed in the browser.
  - `audience: {label}`, `review: {role_label, work_id, task_id?}`, `drafted_by: {agent, from: string[]}` (G-SCR08-5). Without `work_id` or `task_id` the page is read-only (it never guesses a task). `drafted_by` renders "Drafted by <agent> from <from joined>".
  - `returned?: {by, role, at, note?}` (G-SCR08-7; alternative `tasks[].decision.chain.steps[].note` is read too, whichever the mock sends first, `returned` wins).
- **E-PROJECT** `GET /api/v1/projects/{case_id}`: `title`, `pm`, `tab_counts` for the frame and tab bar (existing `useProject`).
- **E-WORK-ITEM** `GET /api/v1/work/{work_id}`: the decision task `review.task_id` (`id`, `revision`, `you_can_act`, `cannot_act_reason`, `decision.changes`, `decision.prepared_by`, `decision.chain`), `workspace.agent_note`.
- **E-PROJECT-TAB** `GET /api/v1/projects/{case_id}/documents`: existing typed `documents[]` (`document_id, title, kind?, version, status, updated_at?, test_template?, work_id?`) for the Documents list (item 2); the mock now answers it from `fixtures/projects/tabs/<case_id>.documents.json` (P-0102 has `tab_counts.documents: 3`; the SOW row is the review fixture).

### Writes (the same as `/work/[id]/decide`)
- **E-TASK-CLAIM** `POST /api/v1/tasks/{task_id}/claim` body `{expected_revision}`; **E-TASK-DECIDE** `POST /api/v1/tasks/{task_id}/decision` body `{expected_revision, verdict: "approve" | "return", note?}`. CSRF header as the client already sends. A return needs a non-empty note (max `NOTE_MAX`, 2000); approve sends no note. `expected_revision` is the revision as last read. Claim happens first when the task needs it, once per task revision, exactly as `useDecision` does.
- Errors: 401 sign-in view; 403 and 404 look the same ("not open to you", no hint a record exists); 409 stale: the generic message, re-read, no auto-retry; 422 inline on the note; network or 5xx: re-read the work item before offering a retry, never show "approved" from the click, never resend automatically (uncertain effect). A failed re-read leaves the buttons off with "Try again" that only reads.
- Permission and tenant: `you_can_act` per task decides whether controls exist; roles, personas and the "PMO Lead" label never grant one. `cannot_act_reason` (`prepared_by_you`, `not_your_role`, `already_decided`, `not_your_turn`) is shown via the existing `cannotActCopy` wording. A user without access to the case gets 403/404 on E-DOCUMENT.
- Idempotency and versioning: the page is keyed by `?v=<version>`; the latest version is never guessed, so a missing or non-numeric `v` reads as not found. An approval on one version is never shown on another. The decision write is guarded by `expected_revision`; nothing is retried automatically.

### Screen states (route `/projects/[caseId]/documents/[documentId]?v=`)
- **Loading:** the shared `LoadingState`; no controls.
- **401:** `SignedOutState`. **403/404:** one "not open to you" state, the same for both. **Error / 5xx:** error card with "Try again" that re-reads.
- **Success, awaiting review (default, boards SCR-08-desktop, SCR-08-mobile):** crumb, heading "<title> · v<n>", status tag (backend `status` text), TEST TEMPLATE tag when `test_template`, "Drafted by …" line, `decision.changes` list (item 5), the numbered sections (changed section tinted, agent note in its own labelled block under its section; the phone shows "<agent> flagged section <n>" taken from the first note's section key and heading), Checks panel, Audience rows, "Your review · <role_label>" when sent, the note field, "Approve v<n>" and "Return with note". The paragraph "Approving records your name and time. Approving does not send it to the client." sits under the buttons.
- **Cannot act:** same page, no buttons or note field, a plain sentence from `cannotActCopy` (including `prepared_by_you`). No `task_id`: read-only with "This review isn't open to you here."
- **Deciding:** buttons busy, one write at a time; "Return" with an empty note shows the field error and sends nothing.
- **Done (item 14):** approved: Callout from the re-read, no controls. Returned: the returned state.
- **Returned (boards `-returned`):** tag "RETURNED TO PM", "Returned by <name> (<role>) · <time>", the quote, the three rule sentences (item 13), Tola's panel, the two held buttons (item 1), the sections below (item 4). The note shows only where sent (item 12).
- **Empty:** a document with `sections: []` shows "This document has no sections yet." and the checks that came; a document with no `sections` field at all shows the `body_url` as a "Download" link plus "The text isn't available here." `body_url` is a link only, never embedded or fetched.
- **Unknown values:** a missing status, template, audience or check detail reads "Unknown" or the part is hidden as stated above; never blank, never 0.
