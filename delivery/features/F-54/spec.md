# F-54 One paging footer inside the table, and History laid out like Overview

Task: FE-PAGING-CONSISTENCY (coordinator-defined, at the design engineer's request on 20 Nov; see readiness.md). No endpoint, contract or data change. Rules: D-PAGING r2 (10 / 20 / 50 rows per page on every list, newest first; default changed to 10 by the design engineer on 20 Nov, D-137) plus the design engineer's 20 Nov direction: the paging is part of the table, identical on every list, never a dropdown. Design check passes under EXCEPTION D-89 as for F-53; this decision supersedes the boards' separate paging footers and the History tab's separate header.

## Rules
- Use and extend shared components in `frontend/src/components` only. Build ONE shared paging footer (extend `ShowMore`, or a new shared component that replaces it, plus a `Table` option to draw it inside the table frame). Every list uses it; no list draws its own paging markup or CSS.
- The footer, left to right: the count ("20 of 74 showing", "All 74 showing", or "20 showing" where the total is unknown), then "Rows per page" with 10 / 20 / 50 as a segmented button group (the shared Segmented look, not a Select), then the Show more button when there is more. At phone width it wraps; every target is at least 44 by 44 px.
- Rows per page starts at 10. Choosing a larger number ADDS rows to the table: the rows already shown stay in place, only the extra rows are fetched (or revealed) and appended; the table never blanks, reloads from the first page or shows a full loading state. Choosing a smaller number trims the shown rows back without a fetch. Filter and sort are kept, and keyboard focus stays on the chosen option.
- An option that would show nothing more is inactive (disabled, not hidden): an option is inactive when the list's total is at or below the next smaller option (3 rows: 20 and 50 inactive; 15 rows: 50 inactive). Where the total is unknown (cursor lists), larger options stay active while there is more to load. Where a list keeps the choice in the URL today (My work `limit`), keep doing so.
- Lists drawn as cards on phones (History, My work) put the same footer directly under the last card, in the same frame style.
- Don't change wording, data or behaviour beyond paging and the History layout.
