## Contract

### Endpoints (all unchanged)
| Operation | Request | 200 | Errors | Permission and tenant |
|---|---|---|---|---|
| E-WORK-ITEM `GET /api/v1/work/{work_id}` | path id | WorkItem with `tasks[].decision`, `you_can_act`, `cannot_act_reason`, `asked` | 401 signed-out callout with `next`; 403 and 404 `NoAccessState` (shows nothing about the item); 5xx or network `WorkErrorCard` with Try again | Backend decides per record. The page never infers authority from `/me`. |
| E-TASK-CLAIM `POST /api/v1/tasks/{task_id}/claim` | `{expected_revision}` = the task's `revision`; CSRF header | `{task_id, revision, claimed_by}` | 409 stale view; 403 read-only view; 422 message shown, controls stay off; network: Try again | Once per `task id:revision`, also under StrictMode. |
| E-TASK-DECIDE `POST /api/v1/tasks/{task_id}/decision` | `{verdict: approve | return | reject, expected_revision, note?}`; CSRF header | `{task_id, verdict, decided_by, decided_at, work_state}` | 409 stale view, never auto-approved; 403 reload then read-only; 422 server message, note kept; network or 5xx uncertain: one reload, no resend | One write at a time. No client retry. |

No endpoint, request or response shape is added or changed. Idempotency and versioning are as F-04 shipped them.

### PROPOSAL: board data the contract has no field for (typed locally)
Typed in a new `frontend/src/features/decide/presentation.ts`, marked `// PROPOSAL (F-16 board data)`, read from the E-WORK-ITEM body by a safe cast under the top-level key `decide_presentation`, as F-14 did with `presentation`. The builder finalises names and lists each field in build.md as a contract proposal with the boards that need it. Shape sketch:

```ts
type DecidePresentation = {
  queue?: {                                   // "DECISIONS / 1 OF 3 / …" and "Next decision · 2 of 3"
    position: number; total: number;
    next?: { label: string; href: string };   // href must pass isAppPath (single leading "/")
  };
  subject?: string;                           // "Lagoon Health, milestone 2": mobile h1 and desktop sub-line
  client?: string;                            // "Lagoon Health": done heading "Invoice v2 for Lagoon Health is approved"
  waiting?: string;                           // "waiting 2h" in the phone station line
  agent?: { role?: string; summary?: string; link_label?: string; note?: string };
  comment?: { label: string; action: string };  // not-yours board only
};
```

Facts details ("v2", "Waiting", "You", "10:47", "Next") and the facts' tones come from F-14's existing `presentation.facts` and `presentation.fact_tones`, read through `presentationOf` and `viewFor`. F-16 does not add a second facts field.

Rules:
1. **Contract first.** Use a contract field wherever one exists. The title is `tasks[].title`, the rows are `tasks[].decision`, the chain is `decision.chain`, the "Asked" line is `task.asked`, the done facts and next step are the reloaded item's.
2. **Hide when absent.** With no `decide_presentation`, every element renders exactly as the F-04 page does today. That covers W-1201 to W-1208 (all unchanged files) and any live response.
3. **Unknown wins.** An unknown or absent amount reads "Unknown" whatever the block says (INV-UNKNOWN). A fact whose contract status is `unknown` reads "Unknown" whatever `presentation.facts` says, and the contract status word stays in the accessible text, as in F-14.
4. **Links are navigation only.** `queue.next.href` renders only when `isAppPath` accepts it. Absolute, `//` and `javascript:` hrefs are dropped.
5. **No new write, and no dead control.** The pager and "Next decision" are links or plain text. The not-yours comment box is built as in "Controls the boards draw" below. Nothing the block carries is ever sent to any endpoint.

### Reaching the done and stale states for the fidelity check
`fidelity.mjs` scores one URL and cannot click. The builder adds `delivery/features/F-16/round-<N>/fidelity/drive-states.mjs`, which for each of done and stale and each width: resets the mock (`POST /__mock/reset`), opens the URL above with the persona cookie in Playwright, clicks Approve v2 through the real UI, waits for the done heading or the stale heading, and saves the rendered document with scripts removed and `<base href="http://localhost:4601/">` added to `round-<N>/fidelity/frozen/<state>-<width>.html`. A static server on port 4603 serves that folder. The fidelity command then uses `--page http://localhost:4603/frozen/<state>-<width>.html`. Every other board uses the live page URL. build.md states which boards used a frozen page. No mock handler or product code is changed for this.

## Assumptions
- New W-18xx fixtures carry the board data; the W-12xx files and their tests stay untouched. Reason: the F-04 tests pin those files, and F-14 used the same split.
- One optional top-level `decide_presentation` key, separate from F-14's `presentation`. Reason: it keeps the proposal in one removable place and avoids editing F-14's schema in the test.
- The persona is `finance_lead` on all boards. Reason: eligibility is the fixture's, not the persona's; the Bisi name is a frame exception.
- "Decisions" links to `/my-work`. Reason: no decisions list screen exists in scope and the queue lists decisions.
- Facts details reuse F-14's `presentation.facts` and `fact_tones` through read-only imports. Reason: avoids a second field for the same thing without editing `work-item/**`.
- The frozen-page driver is accepted as the way to score done and stale. Reason: the tool cannot click and the mock must not change; the approver may escalate this to the design engineer.
- The disabled comment box (item 13) is the default. Reason: the readiness brief asks for "drawn but inert or hidden-when-absent" and a live-looking box would claim an effect. The approver may escalate this to the design engineer.
- Ports 4601, 4602 and 4603 are not used by any other feature's spec.
- One PR for all 10 boards; if 90 is not reached on a state within the round limit, continue as a recorded extra round on the same branch (D-47 precedent).
