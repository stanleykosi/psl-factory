## Summary
- Every frontend reference to the API contract moves from v4 (and one stray v3) to `architecture/packages/v7/openapi.json`, with one constant as the source for the tests.
- `src/api/schema.d.ts` is regenerated by `npm run gen:api` only, and the drift test pins it to v7.
- Every fixture and handler on the base validates against v7 with no fixture edits. For the six mocked operations, v4 to v7 is additive: E-ME and E-WORK-ITEM gain optional proposal properties, nothing is removed and no `required` list changes. The builder proves this with the tests and does not assume it.
- No screen, copy, style, handler or fixture changes. The base has no proposal-field strip (F-06 is unmerged and `frontend/mock/exceptions.mjs` is absent), so nothing is removed today. Open lanes drop their own strips when they rebase.
- One new guard test makes sure the mock, `gen:api` and the drift test all point at the same package, so a stale path cannot come back unnoticed.

## Contract
No new or changed operation is built here. The frontend binds to the v7 definitions of the operations it already mocks:

| Operation | Method/path | Statuses the mock can return | Change v4 to v7 |
|---|---|---|---|
| E-ME | GET /api/v1/me | 200, 401, 403, 404 | optional proposal fields added |
| E-WORK-LIST | GET /api/v1/work | 200, 401, 403, 404 | none |
| E-WORK-ITEM | GET /api/v1/work/{work_id} | 200, 401, 403, 404 | optional proposal fields added |
| E-WORK-HISTORY | GET /api/v1/work/{work_id}/history | 200, 401, 403, 404 | none |
| E-TASK-CLAIM | POST /api/v1/tasks/{task_id}/claim | 200, 401, 403, 404, 409, 422 | none |
| E-TASK-DECIDE | POST /api/v1/tasks/{task_id}/decision | 200, 401, 403, 404, 409, 422 | none |

- Permission and tenant behaviour of the mock is unchanged:
  - personas through the `psl_mock_persona` cookie (`finance_lead`, `pm`, `none`);
  - scenario statuses through `X-Mock-Scenario` or the `psl_mock_scenario` cookie, applied only when the operation declares that status;
  - W-1099 is the no-access work item (404);
  - claim and decide validate the body against the v7 request schema and check the task revision (409 on a stale revision, 422 on an invalid body);
  - CSRF failure answers `csrf_failed`.
- Fixtures are the existing files under `frontend/mock/fixtures/**`, byte-for-byte unchanged. Proposal-only fields that v7 declares (for example `assistant_agents`, `allowed_actions`) are not added to fixtures in this feature.
- Screen states: none change. Loading, empty, error and success on My work, the work item and the decide flow behave exactly as on the base, which the existing unit and Playwright suites cover.
