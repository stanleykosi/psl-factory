## Findings
- UI-2-1 | blocking | high | frontend | The phone sections have lost the board's panel. SCR-25-mobile-review and SCR-49-mobile-blocked both draw each section as a white box with a 2px ink border and a 14px inner inset. The frame at 390 removes the border and the inset (`workspace.css:139-142`: `.ws-section { border: none }`, `.ws-section__body { padding: 0 }`, head `padding: 0 0 6px`), so rows run flush to the page gutter. D-62's wording ("no panel border on phones") does not match these two boards. The boards are the spec, so please ask the design engineer to confirm. Fix: at <=720px keep `.ws-section` with `border: 2px solid var(--ink)`, give `.ws-section__body` 0 14px 6px and the head 10px 14px 6px, and keep the head unfilled as now. I injected these rules on W-2001 and W-2003 at 390: the result reads like the boards and there is no sideways scroll. That run was a check only and nothing was committed.
- UI-2-2 | blocking | medium | frontend | Row end values wrap under the text when they should stay on the right. At 390 on W-2001 and W-2003, "2 RECORDS", "ISS-0233", "MIN-0141", "HELD", "DONE · 22 Mar 2027" and "MEDIUM" drop to their own line. SCR-25 and SCR-49 mobile keep them on the right and wrap the words instead. Cause: `.ws-row__main { flex: 1 1 auto }` (`workspace.css:71`) with `flex-wrap: wrap` on `.ws-row`. Fix: `.ws-row__main { flex: 1 1 0; }`. Row forms still wrap, because `.ws-row__form` stays at 100% basis. I checked this by injection at 390.
- UI-2-3 | blocking | medium | frontend | The phone pinned Decide bar doesn't match the boards' bar. (a) On first view at 390 on W-2001 the bar's lower part (Refuse and its reason) is cut off below the fold. The sticky containing block is `.ws`, which begins where the bar sits, so the bar cannot rise any further. Measured: bar top 665 and height 252 against a viewport of 844. (b) The 2px top rule and the white band stop at the page gutters. On the SCR-25, SCR-26 and SCR-49 phone boards they run edge to edge, with the buttons inset 16px. Fix: at <=720px give `.ws-decide` `position: fixed; left: 0; right: 0; bottom: 0; padding: 12px 16px 18px`, and reserve its height at the end of the workspace (padding-bottom). Alternatively, attach the sticky bar to a full-width wrapper outside `.ws`.
- UI-2-4 | blocking | medium | frontend | Tables break their reference cells and crush at phone width. "R-07" wraps to "R-" / "07" at 1440 as well as 390 (W-2002, Requirements table). At 390 the requirement column falls to one word per line, while the Pricing table on the same page scrolls. SCR-26 draws R-07 on one line. Fix: give reference and cite cells `white-space: nowrap` (`.ws-table td.psl-mono, .ws-table .ws-cite`), and give `.ws-table` a minimum width (for example `min-width: 560px` inside the scrolling `.ws-tablewrap`) so narrow screens scroll instead of squeezing.
- UI-2-5 | blocking | medium | frontend | The cite in a table cell and the status tag don't follow SCR-26. The board puts the source ("RFP p.6") on its own line under the requirement, in 12px muted sans with normal case, and sets the tag in capitals ("SUGGESTED BY TOLA"). The frame puts the cite inline as uppercase mono ("RFP P.6") and the tag in sentence case. Fix: inside `.ws-table`, show the cell link or cite as a block line in 12px `--ink-muted` sans with no uppercase, and give table tags `text-transform: uppercase; font-weight: 600`. Measured gap: table 1440 76.3, 390 74.3. Also put the "0 selected · Accept selected · hint" footer on one row, as the board does (count, then button, then hint), instead of stacking the three.
- UI-2-6 | blocking | medium | frontend | A suggestion card doesn't use the fields it already has the way SCR-26 draws them. The `suggestions` item carries `label`, `text`, `detail`, `tag` and `cites`, which are what the board's card shows: a mono reference line, an answer box with an `--action` border on `--action-tint`, then the source line in 12px muted. The frame runs label and text together in one bold-led line. It also repeats "Suggested by Tola" (agent meta line plus tag) and "RFP P.6" (cite plus label). Several items stack with no separator. Fix: show `label` as a mono line on its own, `text` in the tinted answer box and `detail` beneath it. Drop the agent line when the tag already names the agent, and put a 1px `--rule-soft` divider between items. Measured gap: suggestions 1440 46.9. The Status radio group and the "Write my own" button are not in the data (see B list).
- UI-2-7 | blocking | low | frontend | Several word styles don't match the boards. (a) The checklist and findings status pills are in mono (they inherit `.ws-row__end`'s `--font-mono`). SCR-49 and SCR-44 draw them in 12px semibold sans. Fix: give `.ws-rows--checklist .ws-word, .ws-rows--findings .ws-word` `font-family: var(--font-sans); font-weight: 600`. (b) Money in table cells uses `.psl-amount`, which is the 16px/500 headline amount style used on decision cards (`psl-bundle.css:391`), so table numbers are larger than the row text. SCR-56 draws them at row size. Fix: `.ws-table .psl-amount { font-size: inherit; font-weight: 400 }`. (c) The step form's submit button takes the opening step's emphasis, so "Edit answer" submits with a white secondary button (`StepForm.tsx:320`, `stepClass`). SCR-26 edit draws the form's submit as a filled primary. Fix: always give the submit button inside `.ws-form` the primary class, unless the step is `danger`.
- UI-2-8 | non-blocking | low | frontend | On desktop the checklist draws a check mark for each row. SCR-49 desktop has no marks and lets the pill carry the state, while SCR-44 readiness passes at 91.3 either way. The marks are harmless, but ask the design engineer whether the frame should drop them at every width, as it already does on phones.
