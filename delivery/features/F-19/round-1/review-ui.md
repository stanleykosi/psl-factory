## Findings
- UI-1-1 | blocking | medium | frontend | Save button restyled on both detail boards. Expected: SCR-35-desktop-detail and SCR-35-mobile-detail draw the Save as a blue primary button (`background:#2459D6`, white text, 50px), shown with the inputs empty. Actual: the button uses the shared disabled style (grey `--disabled` fill, muted text) until both inputs are filled, so on the drawn state it is grey (frontend/src/features/clients/BillingContactForm.tsx:225, `disabled={busy || !name.trim() || !email.trim()}`). The spec says "off until both inputs are non-blank" (spec.md line 48, acceptance 10), but that is not listed among the spec's Conflicts, so D-71 does not cover it. Fix: keep the button enabled and blue, and on a press with a blank input show the field message beside that input and focus it (the spec already has "client-side checks refuse only blank values", and the 422 path already draws per-field messages). Keep `disabled` only while busy. Spec line 48 and acceptance 10 then need the matching one-line change. The other option is for the design engineer to approve the grey disabled state as an exception.
- UI-1-2 | blocking | medium | frontend | Empty contact inputs restyled. Expected: both boards draw "Billing contact name" and "Billing email" with a 2px `#C8401C` (`--signal`) border when no contact is set. Actual: plain ink border (`psl-input`) (BillingContactForm.tsx:184/209). The approved exception covers only the "Not set" placeholder text, not the border. The border is driven by the backend's `billing_contact.set === false`, the same flag that already shows the "Needed before any invoice can start" helper, so the page decides nothing. Fix: add a token-based modifier (border-color `var(--signal)`) while `set` is false and the field has no 422 error (the error style wins).
- UI-1-3 | blocking | medium | frontend | Phone detail: Save is not in a sticky bottom bar. Expected: SCR-35-mobile-detail draws a white bar fixed at the bottom of the screen (`padding:12px 16px 18px`, `border-top:2px solid` ink) holding a full-width blue Save. Actual: Save sits inside the form card under the email input, and the bottom of the screen shows the Projects and Money panels. A precedent already exists: `.monthend-bar` in frontend/src/features/finance/month-end/month-end.css:63 (sticky, surface, ink top rule, same padding). Reuse that pattern below 720px. The status line, notice and errors stay in the form.
- UI-1-4 | blocking | low | frontend | Phone detail: the form is wrapped in a panel the board does not draw.
