## Notes
- `LineContext.state?` is optional only in the type: the live page always sets it. A lane form that indexes by it (for example `STATE_TAGS[ctx.state]`) now has to handle `undefined`, and tsc will flag any place that does not. No lane form uses it yet.
- Sharing the store makes the rule one write per work item, across the controls row and every line form, where it used to be one write per component. That is stricter and matches "one write at a time". Command ids follow `'<line>.<action>'` / `'work.*'`, so `pending` and the lock keys do not collide between the row and the lines.
- The unread marker is matched by object identity. Lines compare it to the shared `ctx` and the controls row to `item`, so an unread controls write does not disable line forms, and the other way round. This is no worse than before (it was per component), and the server's `expected_revision` check still answers a stale line write with 409. If you want it item-wide, compare both sides to `ctx`, or to the read's `loadedAt`.
- The `'item'` fallback scope applies only when a caller passes neither `workId` nor `id`. Today only the bare hook tests do that. Making the scope required would stop a future caller from silently sharing it.
- `import { useSyncExternalStore } from 'react'` sits mid-file in `useWriteLock.ts`. That is style only, and lint passes.
- Other test files that render `LiveWorkItemView` (`live-work-item.test.tsx`, `line-adapter.test.tsx`) do not call `resetScopedWriteLocks`, but they make no writes, and Vitest isolates each file.
