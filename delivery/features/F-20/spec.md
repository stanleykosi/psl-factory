# The Templates tab on Setup lists each document template and uploads a new version of one

> Tasks: FE-SETUP-TEMPLATES (F-11D; R-SETUP; acceptance A-TEMPLATE-VERSION, A-ACCESSIBILITY). Architecture: package `architecture/packages/v7`, manifest sha256 in `manifest.sha256`; D-TEMPLATES-VIEW r1 (`architecture/model.json:1435`, status `proposed`). Design: approved canvas version 1794581312-b166 (`design/review.json`; the coordinator ran `design.py check`: passes, client-approved 13 Nov). Screens: SCR-34, two artboards (`SCR-34-desktop`, `SCR-34-mobile`). Model: `delivery/features/F-18/spec.md`.

## Summary
- `/setup/templates` stops being a placeholder. Inside the existing `SetupFrame` it lists the document templates in the order the API returns them, each with its line, name, current version, test-template badge and who changed it last and when, from E-TEMPLATES.
- A person whose row says `can_upload` can upload a new version (a file, an optional note up to 2000 characters) with E-TEMPLATE-VERSION. The new version then shows as current, with the badge exactly as the backend returns it.
- `test_template` is the backend's fact. The UI never sets it, never infers "PSL's own" from a missing field, and never guesses it after an upload.
- A stale upload (409) shows the API message, reloads and drops the person's chosen file. It is never re-applied to a newer version. A network error is never retried before a reload.
- Everything runs on the **contract mock only**. D-TEMPLATES-VIEW is `proposed`; it is used under the recorded early-start exception (`architecture/sources/decisions-2026-11-14-v2.md` (e)-(g)): the backend developer may change or refuse any field, nothing is released and PSL approval is still needed. The PR must not claim a real backend.
- Both boards pass the fidelity tool on the mock at their own width (coverage 100% after approved exceptions, visual >= 90).

## Contract

### Operations (v7 types, D-TEMPLATES-VIEW r1 proposed; this feature builds against them)
| Operation | Request | 200 | Errors | Permission, tenant, idempotency |
|---|---|---|---|---|
| E-TEMPLATES `GET /api/v1/setup/templates?cursor=` | optional `cursor` (the value of `next_cursor`) | `{items[], next_cursor?, as_of}` | 401 `SignedOutState` with `next` = this page; 403 and 404 the same not-open view, no template name shown; 5xx or network `WorkErrorCard` with Try again | Backend decides per person. Nothing inferred from `/me` beyond the existing Setup destination gate. |
| E-TEMPLATE-VERSION `POST /api/v1/setup/templates/{template_id}/versions` | `{expected_revision, filename, content_base64, note?}` + CSRF; `expected_revision` is the row's `revision` exactly as read (0 is sent as 0, never omitted); `note` is omitted when blank | `{template_id, version, test_template, revision}` | 401 signed-out; 403/404 not-open view; 409 show the API message, reload, clear the selection; 422 mark the named `fields[]`, message in a `role="alert"` callout, keep the entries; network/5xx: uncertain, see below | One write at a time per page. No idempotency key: a repeat after success fails on `expected_revision` (409). The double-press guard is the protection. |

Rules for what the page shows (every element is drawn from a returned field; a missing field leaves its element out, never a placeholder, never board copy):
1. **Rows** in the order returned. Name = `name`; line = `line`; version = `version` (shown as returned, not prefixed or reformatted); `kind`, `updated_by`, `updated_at` and `versions` appear only when returned. `updated_at` shows as a Lagos day ("12 Nov"; year added outside the current Lagos year, as `versionText` does). `versions` shows as a number only ("4 versions"); no history, download or rollback (Out of scope).
2. **Badge** "TEST TEMPLATE" (the board's tag, `.psl-tag` warning tone) shows when `test_template === true`. When `test_template === false` no test badge shows and nothing says "PSL's own" or any other claim (Assumptions). `test_template` is required in the schema; a row where it is not a boolean is treated as `true` for display only because the safe wording is the test one (Assumptions).
3. **Banner / note** (board copy, exact). The amber banner "Every document currently uses a test template. When PSL supplies its real template, upload it here; documents already sent keep the template they were made with." (desktop) and the line "All {n} are test templates until PSL supplies its own." (phone, {n} = `items.length`) show only when the list is non-empty, every returned row has `test_template === true` and there is no `next_cursor` (so "every" and "all" are known to be true). Otherwise neither sentence shows and each row's own badge speaks.
4. **Count** "{n} TEMPLATES · {m} TEST" (mono 12px, as drawn) from the loaded rows when there is no `next_cursor`; with `next_cursor` it reads "{n} SHOWN · {m} TEST". "As of {Lagos date and time}" from `as_of` appears in the same line group (undrawn, see Conflicts 6).
5. **Upload** control "Upload PSL's version" shows only on rows with a `template_id` and `can_upload === true`; it is a `button` that opens an inline panel under that row (Conflicts 3). A row without `template_id` or without `can_upload === true` is read-only: no control, no placeholder, no disabled button. The label is the board's; for a row with `test_template === false` the label is "Upload a new version" (Assumptions).
6. **Upload panel** (one open at a time; opening another closes the first and drops its selection): a file input (label "File"), the chosen file name and size, a note textarea "Note (optional)" with a 2000-character counter and an over-limit refusal before any request, and buttons "Upload version" and "Cancel". "Upload version" is off until a non-empty file is chosen; a zero-byte file is refused with a message, no request. The file is read in the browser to base64 (`FileReader`/`arrayBuffer`); `filename` = the file's name. The panel states "This replaces the current version for new documents. Documents already sent keep theirs." only if copy for it is approved (Conflicts 3); otherwise omitted.
7. **Send flow.** One press: disable the button synchronously (a ref guard, so a double press makes one request), show "Uploading…", POST. **200:** close the panel, reload E-TEMPLATES once (cursor reset to the first page), move focus to the updated row's name, announce "Version {version} uploaded for {name}" in a polite live region; the row shows the version and badge from the reload, not from the 200 body (the 200 body is used only if the reload fails: then that row alone shows `version` and `test_template` from the 200 and the page shows "Uploaded. We couldn’t refresh the list."). **409:** show the API message, reload, clear the chosen file and note, close the panel. **422:** mark the field(s) named in `fields[]` (`name` matches `filename`, `content_base64` or `note`; the file input takes `filename` and `content_base64`), put `message` in a `role="alert"` callout, keep the entries. **401:** `SignedOutState`. **403 / 404:** reload; if the reload gives 403/404 the not-open view shows, else the row loses its control. **Network or 5xx:** show "We couldn’t confirm the upload. Checking the list…", reload once, never resend; if the reload shows a higher `version`/`revision` than before the press, say "The upload went through." and clear the selection; if it does not, the person may press again deliberately with the reloaded `revision`; if the reload fails too, the upload control stays off and "Try again" only reads the list.

## Conflicts
Each place the contract, the existing code or this spec adds, moves or removes something a board draws. The design engineer decides before the build; each is an exception candidate, provisional until signed.

Board versus contract (the contract returns or needs something the board does not draw, or draws something the contract does not carry):
1. **Phone title size.** The phone board draws `h1` 22px; `.setup-phone-title` and the other Setup phone titles are 26px (`.setup-title` is 26px at phone). Recommend: keep the F-11 phone size (26px), same precedent as F-14, F-16 and F-18; exception on the size.
2. **Phone cards draw only name and tag.** The contract gives `line`, `version`, `updated_by`, `updated_at`, `versions` and an upload right, and readiness requires them. Recommend: add under the name a quiet `line` text, a one-line meta ("v3 · PDF · 4 versions · Changed by Ada Okafor, 12 Nov") and, where `can_upload`, a full-width "Upload PSL's version" button (44px). All are extra elements; one exception group, text only. Alternative: leave the phone read-only (rejected: the outcome says the upload works at 390).
3. **Upload panel is not drawn.** Both boards show only a link "Upload PSL's version" (`href="#"`); no file chooser, note, confirm or error is drawn, and the request needs `filename`, `content_base64` and optional `note`. ## Out of scope
- Download, preview, delete, or rollback to an older version; a version history list (the `versions` count is a number only). None are drawn and no endpoint exists.
- Any change to `architecture/**`, `src/api/**`, `openapi.json`, `src/shell/**`, `package.json`, the lock file; a new npm dependency.
- The other Setup tabs (F-11B, C, E, F). Document generation that uses a template (SCR-08, the invoice preview). Real PSL templates and real file storage (FE-CONNECT).
- Virus scanning, file-type or size policy (the backend owns it; the UI shows the 422 it returns).
- Using `ProofField` or E-EVIDENCE-UPLOAD (templates have no case; the file goes in the version request).
- Deciding, labelling or computing "PSL's own": the UI shows only `test_template` as returned.
- Any rule on who may upload; `can_upload` is the backend's per-row right.
- Automatic or background upload, automatic retry of the write, saving a draft of the note, drag-and-drop, multiple files at once.

## Assumptions
- No test badge, and no other claim, on a row with `test_template: false`. Reason: no board draws a "PSL's own" state, and the 13 Nov decision says the backend's flag is the only source.
- A non-boolean `test_template` displays as a test template. Reason: the schema requires a boolean; showing the safe wording on malformed data avoids implying a template is PSL's own.
- The mock never returns `test_template: false`; the false case is covered only by component-test stubs. Reason: no fixture value may be presented as PSL's own template.
- Empty state copy "No templates to show." and the upload-panel field labels are new UI copy in the existing Setup style. Reason: no board draws them.
- The panel is inline, not a modal. Reason: the smallest change using existing Setup patterns; a modal needs focus-trap work no board asks for.
- No client-side file size or type limit beyond refusing a zero-byte file. Reason: the backend owns file policy and the contract carries no limit; a 413 or 5xx from a too-large file shows the generic uncertain notice.
- After a 200, the list is reloaded and the reloaded row is shown, not the 200 body. Reason: the list holds `updated_by`, `updated_at` and `versions`, which the 200 does not return.
- `cursor` is sent as a query parameter though the generated GET declares none. Reason: it is the same proposal the rules list uses and the readiness scope asks for paging; the cast stays in `api.ts` and is listed for the backend developer.
- The mock's scenario and save cookies copy F-11's names with a `templates` suffix; mock ports 4641 to 4643 are free. Reason: F-18 used 4621 to 4623.
- The phone search is not built (the phone board draws none).
