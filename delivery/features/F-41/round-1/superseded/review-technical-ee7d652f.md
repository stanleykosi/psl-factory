## Findings
1. TECH-1-1 | non-blocking | medium | frontend | frontend/src/features/workspace/useWorkspaceStep.ts:118-120, frontend/tests/payment-reminder.test.tsx:168-175. On a 200 `done`, the shared frame sets the green "Done: Send reminder." notice before `await page.reload()`. So a success callout drawn from the 200 body shows while the re-read is in flight, and it stays when the re-read still serves the unsent draft. AC 15 says the page says nothing about sending until the re-read. The test's regex `/\bSent\b|Delivered|Received/` does not catch "Done: Send reminder.", so the test proves less than build.md claims. This is accepted F-17/F-28 frame behaviour ("Done: Approve and send."), so it does not block here. Expected: the coordinator records it as accepted frame wording for a client send, and the test asserts the exact notice. Alternatively, a frame task moves `setNotice` after the reload, with its own test, because `useWorkspaceStep` is read-only for this lane.
2. TECH-1-2 | non-blocking | medium | integration | frontend/tests/payment-reminder.test.tsx:242-254, frontend/src/api/client.ts. AC 16 asks that a 60 s timeout "do the same" as a 5xx: re-read, show the uncertain item, keep Send off. The API client has no timeout, so a hung send leaves the button busy indefinitely. It never resends, so INV-RESEND is safe, but it never re-reads or shows the uncertain notice either. If the person reloads during the hang, the lock is gone until the backend marks the item uncertain. The builder disclosed this. Expected: record it as a deviation, and add a frame-level request timeout that maps to the network-failure path to the backlog. The backend's server-side resend refusal (BACKEND-HANDOFF priority 1) remains the real guard.
3. TECH-1-3 | non-blocking | low | frontend | frontend/src/features/finance/payments/PaymentsView.tsx:363-366. The search `<form onSubmit>` calls `applySearch(text)` with no `SEARCH_MIN_CHARS` check, so pressing Enter on a single character sends `q=H`. AC 8 says none for one character; typing is correctly gated by `SearchField`. Expected: apply the same 2-character rule on submit, or note the choice.
