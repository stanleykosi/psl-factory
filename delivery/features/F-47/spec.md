## Summary
- In the Start work drawer, the Proof box is live on minutes and change and on two new Finance lines, income schedules and ledger sources. A chosen file uploads at once to the line's case, shows "Uploaded · <size>" only after the backend returns an `evidence_id`, and is then sent with the start.
- The case and revision come only from the line (fixed case) or from the chosen project. Each upload carries the revision the last one returned, and the start sends the last one. A 409 on either re-reads where the revision came from and keeps what was typed.

- No size or type rule in the browser, no grant from roles or `/me`. File names and backend messages render as plain text, and the drawer has no download link.

### E-EVIDENCE-UPLOAD `POST /api/v1/cases/{case_id}/evidence`
- **Request:** `{kind: <field.evidence_kind>, filename: <the chosen file's name>, content_base64, case_revision}`, header `X-CSRFToken`, through `useEvidenceUpload` only. `case_id` and the first `case_revision` come from `resolveCase` (the chosen project option, or the fixed line as last read). Every later upload sends the revision the previous upload returned. There is no `accept` attribute, no size check and no type check in the browser.
- **200:** the card shows "Uploaded · <size>" only when the body has a non-empty string `evidence_id`. A 200 without one reads "Not uploaded · Couldn't upload. Try again." and nothing is sent for it (one additive guard in `useEvidenceUpload.ts`, which also protects F-09 and F-31). The returned `case_revision` becomes the revision for the next upload and for the start.
- **Errors:** 401 → the drawer's signed-out state. 403 → "You can't add proof to this item." 404 → the same sentence, as a notice in the drawer, with nothing showing whether the case exists. 409 → the hook re-reads through the start form's revision source (E-LINES or E-LINE-OPTIONS, PMO-0-3), and the card reads "This item changed. Add the file again." 422 → the backend message as text. 5xx, network failure or timeout → "Couldn't upload. Try again."; Try again re-reads the revision first and resends the same bytes. Nothing resends by itself.
- **Permission and tenant:** the picker exists only on a line E-LINES returned, and on a project-scope line only after a project option carrying `case_id` is chosen. No role or `/me` check.
- **Mock (new start-work branch):** `server.mjs` gets one dispatch branch, placed before the response branch. It sends an upload to `start-work.mjs` when the body's `kind` is an `evidence_kind` of a line served to the persona and the `case_id` is one that line can start on (its fixed case, or a `case_field` option served to the persona). Any other upload goes to the F-11 or F-09 owners unchanged. The branch applies CSRF and `psl_mock_scenario`/`X-Mock-Scenario` as the M1 path does, then: 404 if the case isn't served; 409 if `case_revision` isn't the current one; 422 `{code: "invalid", message}` if `content_base64` is empty, and, as a backend-stated sample, `{message: "EXE files can't be used as proof."}` for a name ending `.exe`; on success it adds 1 to the case revision and returns `{evidence_id: "EV-SW-<case_id>-<n>", sha256 of the bytes, case_revision}`. The revision map (`persona:case_id` → revision) is filled from the fixtures and shared with E-LINES, E-LINE-OPTIONS and E-WORK-START. `reset()` clears it, along with the issued ids.

### E-WORK-START `POST /api/v1/work`
- **Request:** `{line, case_id, case_revision: <proof.caseRevision() if any upload or reload happened, else the case as read>, intake: {…, <evidence field>: "<evidence_id>" | ["<id>", …]}, idempotency_key}`, header `X-CSRFToken`. Only files whose card says "Uploaded" are sent. A removed file is not sent. An empty optional proof is not sent.
- **When Start is off:** while any upload is running or any file is failed (Conflicts 5); while the project is not chosen (F-05); after a 422 until something changes (F-05). Uploading never makes a new idempotency key, and a double press sends one start (PMO-0-2).
- **201:** the drawer closes and the person lands on `/work/<work_id>`: minutes → `W-1403`, change → `W-1405` (existing, unchanged), income schedules → `W-4401`, ledger sources → `W-4402`.
- **Errors (F-05, unchanged):** 401 → signed-out. 403 and 404 → "You can't start this here." 409 stale → re-read the revision, keep every value and every uploaded file, call `proof.sync(<re-read revision>)`, and use a new key on the next press. 409 `idempotency_key_reused` → its message. 422 → field messages inline; `proof` is now inline under the Proof box. 5xx, network failure or timeout → "Check again" with the same body and key, and "If it started, it will appear in My work."; never "started".
- **Mock additions:** the revision check reads the shared map. An evidence value must be an id this branch issued on the same case for the same persona, or the start answers 422 `{name: <field>, message: "That proof isn't on this record. Add it again."}`. A required evidence field left empty answers "Proof is required." (the existing required rule).
