# Start work: pick a line, fill its intake in a drawer, land on the new work item

> Tasks: FE-M2A. Architecture: packages/v6 (commit cfcdd94, manifest.sha256 265984034c113b3d3cc3fef0119bc4e560d8488877fb1b6a91cc71409c47f32e; D-START-INTAKE r1 proposed, built on the contract mock only under the recorded exception; D-LEADERS-START r1 approved). Design: canvas 1794581312-b166 (approved 13 Nov, design/review.json); screens: SCR-04 (states default, validation, lines, weekly, minutes, issue, change, incident, escalation, leadership), with CMP-23 in the CMP-01 top bar and phone bar and CMP-24 callouts.

## Summary
- Anyone whose `/me startable_lines` is not empty sees Start work: the CMP-23 split button in the top bar, "+ Start" in the phone bar. Nobody else sees it, and nothing is worked out from roles.
- The main button opens the drawer for E-LINES `default_line`. The chevron, "+ Start", and the main button when there is no `default_line` (CEO/CTO) all open "Choose a line". The person fills the intake built from `intake[]`, presses start, and lands on `/work/<work_id>`.
- One start request per press, with CSRF, a case revision and an idempotency key. A double press, a network failure, a timeout or a 5xx never starts the same work twice. A 422 names each field, a 409 keeps what was typed and reloads the revision, and a 403 or 404 keeps what was typed.
- The contract mock moves from v4 to v6 in one commit. New mock logic lives in `frontend/mock/start-work.mjs`, with fixtures for 8 lines and 4 personas (pm, finance_lead, ceo, none).
- Not included: proof and evidence fields, money fields, the Finance and payroll drawers, `finance_import` lines, the backend and the real API.

## Contract

### E-ME (GET /api/v1/me), unchanged shape
`startable_lines: string[]` holds line keys (the same as E-LINES `items[].key`). The button shows when the list is not empty. The frontend never reads `roles` to decide anything about Start work.

### E-LINES (GET /api/v1/lines)
- Session only. The response holds only lines this person has `factory.start` on.
- 200 body: `{items: Line[], as_of, default_line?, next_cursor?}`.
- `Line` is `{key, title, group, intake: Field[], subtitle?, case_scope?: 'project'|'fixed', case_field?, case_id?, case_revision?, next?: {station_count?, agent?: 'tola'|'chidi'|'zainab', decided_by?: string[], summary?, journey_url?}, start_via?: 'work_start'|'finance_import'}`.
- `Field` is `{name, label, type, required, help?, placeholder?, options?: {value,label}[], options_source?: 'line_options', depends_on?, evidence_kind?, multiple?, value?, restricted?}`.
- Errors are 401, 403 and 404 as `{code, message}`.
- Fetched every time the button or the chevron is pressed, so grants are current. It is not prefetched on page load.

### E-LINE-OPTIONS (GET /api/v1/lines/{line_key}/fields/{field}/options)
- Query: `parent?` (the value of the field named by `depends_on`), `q?` (sent only when not empty), `cursor?` and `limit`. The drawer always sends `limit=20`.
- 200 body: `{items: {value, label, hint?, case_id?, case_revision?, disabled_reason?, sample?}[], next_cursor?, as_of}`.
- Errors are 401, 403 and 404. Path segments go through `encodeURIComponent`.

### E-WORK-START (POST /api/v1/work)
- Session and CSRF (the existing `csrfMiddleware`).
- Body, exactly: `{line, case_id, case_revision, intake, idempotency_key}`. Nothing else is sent.
- `intake` holds only fields the person filled, keyed by `Field.name`. Each value has the shape for its kind:
  - `text`, `long_text`: string, trimmed. Blank means not sent.
  - `date`: `YYYY-MM-DD` (`<input type="date">`).
  - `date_range`: `{from, to}`, holding the parts that are filled. It is sent when either part is filled.
  - `period`: `YYYY-MM` (`<input type="month">`).
  - `datetime`: ISO 8601 with offset (the `datetime-local` value converted with `new Date(v).toISOString()`).
  - `integer`: a JSON number. Blank or not an integer means not sent.
  - `choice`: one `options[].value`.
  - `record`: one option `value`.
  - `records`: a non-empty array of option values.
  - `display`: never sent.
- Responses:
  - 201 `{work_id, state}`.
  - 401 and 403 `{code, message}`.
  - 404 `{code, message}`: the case is not visible.
  - 409 `{code, message}`: stale `case_revision`, or the mock's idempotency-key reuse with a different body.
  - 422 `{code, message, fields?: {name, message}[]}`.
- A 409 or 422 means nothing was written.

### Case resolution (the frontend never guesses a case)
- `case_scope: 'project'`: `case_id` and `case_revision` come from the option chosen in the field named by `case_field`. If that option has neither, start is disabled and the field shows the hint "This project can't be started on from here."
- `case_scope: 'fixed'`: `case_id` and `case_revision` come from the line.
- `case_scope` absent, or a value that doesn't resolve: start is disabled. The drawer shows the "can't be started here yet" callout (below).

### Idempotency key policy (PMO-0-2, binding)
- A new key (`crypto.randomUUID()`) is created when a line's drawer opens, and is held in component state only.
- While a submit is in flight, start is disabled, so a double press sends one request.
- An uncertain result means a network error, a timeout (`AbortSignal.timeout(20000)` on the POST) or any 5xx. After one:
  - nothing is resent automatically;
  - the fields become read-only;
  - the drawer shows a warning callout: "We couldn't confirm the start. Check again: if it already started you'll go straight to it, and nothing starts twice."
  - The primary button reads "Check again". It resends the same body with the same key, which acts as the re-read. A 201 routes to the work item; a definitive 4xx unlocks the fields.
- A definitive 409 or 422 unlocks the form. The next press uses a new key.
- Closing the drawer (×, Cancel, Back, Esc, scrim) or "change line" discards the key. After an uncertain result, Cancel also says "If it started, it will appear in My work."

### 409 handling (PMO-0-3, binding)
- Keep every value.
- Re-read the revision:
  - `project`: E-LINE-OPTIONS for `case_field` with `q` set to the chosen option's label. Take that option's `case_revision`.
  - `fixed`: E-LINES. Take the line's `case_revision`.
- Show a warning callout: "This project changed since you opened the form. We've loaded the latest version; check your entries and press start again." For a fixed case it says "This record changed…".
- Never resubmit automatically.
- If the chosen option is no longer returned, clear that field and its dependents, and show under it: "That choice is no longer available. Choose again."
- If the line is no longer in E-LINES, show "You can no longer start this line." and remove the start button.

### 422 handling
- Each `fields[].name` that matches a rendered field (display fields included) gets its message inline: `psl-error` under the control, `aria-invalid="true"` and `aria-describedby`.
- A problem callout sits at the top of the drawer body: "<n> things to fix before <Agent> can start." (n is `fields.length`, or 1 with no `fields`). `<Agent>` is `next.agent` capitalised; without it the callout says "before this can start". The head eyebrow also reads "<n> things to fix". Unmatched field messages, or `message` when there are no `fields`, are listed in that callout.
- Focus moves to the callout.

### 403 or 404 on submit
A problem callout in the drawer says "You can't start this here." followed by `error.message`. Values are kept and the drawer stays open. A 401 replaces the drawer body with `SignedOutState`.

### Fields this release does not handle (PMO-0-6)
- An optional field whose `type` is `evidence`, `money` or not in the kind list is not rendered and not sent.
- If a line has a required field of those kinds, or `start_via` present and not `work_start`, its drawer shows only its title and an info callout: "You can't start this line from here yet. Describe it to Tola and she'll help you start it." The callout links "Describe it to Tola" to `/assistant`. There is no start button, only Back/Cancel.
- None of F-05's fixtures contains these cases. The copy goes in build.md for product acceptance.

  - "<station_count> stations.";
  - the agent avatar (`psl-avatar--<agent>`) and name;
  - `summary`;
  - "Decided by <decided_by joined with " or ">.";
  - a "See the full journey" link to `journey_url`.

### Mock behaviour (frontend/mock/start-work.mjs)
- It exports:
  - `START_OPERATIONS = ['E-LINES','E-LINE-OPTIONS','E-WORK-START']`;
  - `createStartWorkMock(openapi)`, which returns `{handle(operationId, {url, raw, persona}) -> [status, body], reset(), started}`. `started` is a Map of idempotency_key to `{body, response}`.
- `server.mjs` gets one line each:
  - the three ids appended to `M1_OPERATIONS`;
  - `'ceo'` in `PERSONAS`;
  - a dispatch line `if (START_OPERATIONS.includes(route.operationId)) return send(res, ...startWork.handle(...))`;
  - `startWork.reset()` in the `/__mock/reset` branch;
  - the `OPENAPI_PATH` repoint;
  - plus the import and the construction next to `validators`.
- The scenario cookie and header and the CSRF check stay in `server.mjs` and keep their current order.
- E-LINES: serve `lines.<persona>.json`.
- E-LINE-OPTIONS, checked in this order:
  1. The line is not in the persona's lines: 404.
  2. The field is not a `line_options` field of that line: 404.
  3. A field with `depends_on` and no `parent`: 200 with an empty list.
  4. Otherwise filter by persona, then `parent`, then `q` (case-insensitive on label), and page by an `o:<offset>` cursor. `limit` is in {10,20,50}, default 20.
- E-WORK-START, checked in this order:
  1. The JSON body doesn't parse, or the Ajv 2020 check against the v6 request schema fails: 422 with `fields` naming each missing or extra property.
  2. `line` is not in the persona's lines: 403 `forbidden`.
  3. The key is already in `started`:
     - with a canonically equal body (sorted-key JSON), return the stored 201 again and create nothing;
     - with a different body, return 409 `{code: "idempotency_key_reused", message: "This start was already sent with different details. Close the form and start again."}`.
  4. Case check:
     - project scope: `case_id` must equal the `case_id` of the option the persona is served for `intake[case_field]`. Otherwise 404 `not_found`.
     - fixed scope: `case_id` must equal the line's. Otherwise 404.
  5. `case_revision` is not the served revision: 409 `stale_revision`.
  6. Intake check, answered as 422 `{code: "invalid", message: "Check the highlighted fields and try again.", fields}`:
     - a required field missing or blank: "<label> is required.";
     - an unknown or display key: "This field can't be sent.";
     - a record or records value not among the options served to the persona for that parent: "Choose one from the list.";
     - a disabled option: its `disabled_reason`;
     - a choice not among `options`: "Choose one from the list.";
     - a malformed date, date_range, period, datetime or integer: "Enter a valid <kind>.";
     - an `invoice` start on project `P-0102` additionally fails with `{name: "billing_contact", message: "The client register has no billing contact for Harmattan Bank. Add one in the project's client details."}` (a name with no matching field, so it goes to the summary).
  7. Otherwise record `started.set(key, …)` and answer 201 `{work_id: "W-14xx", state: "processing"}`.
- Example 201 request (pm), sent with `X-CSRFToken: mock-csrf-pm`:
  `{"line":"invoice","case_id":"C-0101","case_revision":6,"intake":{"project":"P-0101","milestone":"M-0103"},"idempotency_key":"7b0e…"}`. The answer is `{"work_id":"W-1401","state":"processing"}`.

## Assumptions
- Line keys (`invoice`, `weekly_report`, `minutes`, `issue_followup`, `change_request`, `emergency_change`, `escalation`, `leadership_report`), group names and subtitles are mock sample values. The backend will supply the real ones.
- The drawer title is the line `title`. The boards' shorter drawer titles (for example "Weekly client report") have no contract field.
- The primary button labels come from a key-to-label map with a "Start work" fallback, to match the boards. This is copy only, not a rule, and a `start_label` field could replace it later (a question for the backend developer).
- finance_lead's lines become `["invoice"]`, and "Record a receipt" is dropped: it has no line, board or drawer in this scope. Finance lines arrive with FE-M2A-PROOF.
- The ceo persona is Folake Bello (the CEO name used on the canvas), with all 8 lines. That follows D-LEADERS-START; its sample destinations were chosen by me.
- pm gets 2 projects (A-START-INTAKE: "a PM with factory.start on two projects"). The ceo gets 26, so "Show more" is exercised there.
- There is no client-side required check. The server's 422 is the single source of field errors, and only an unresolved case disables start.
- Pickers always request `limit=20`. The 10/50 page sizes are not offered in a drawer.
- After a 409, the project revision is re-read with `q=<chosen label>`, because there is no single-option read.
- Timeout is 20 s. After an uncertain result the form locks so the same key is only ever resent with the same body, and "Check again" is that resend. There is no automatic retry.
- Fetching E-LINES on every press, not on page load, keeps grants current at the cost of one short loading state.
- The 403/404 drawer copy ("You can't start this here."), the stale and uncertain copy, and the "can't start here yet" copy (PMO-0-6) have no board. They go in build.md for product acceptance.
- The "What happens next" order is stations, agent, summary, decided-by. That is close to SCR-04-desktop but not word for word, because the contract carries the parts separately.
- The mock's billing-contact 422 on Harmattan stands in for the validation board's second message. Because it names no rendered field, it appears in the summary callout, not inline as on the board.
