## Summary
- The write path is sound. One press sends exactly one POST, with the options `revision`, `X-CSRFToken` and one of the two contract body shapes. A 409 re-reads the options and keeps the input. A network error, 5xx or unreadable 201 is never resent, and "Check again" only reads. "Milestone recorded" shows only from the re-read, and only when the names match.
- Authority comes from the server alone. "Mark complete" shows only when the options read says `can_complete`, on both the page and the tab. There is no role logic in the UI. Removing the `useMe` destination check does not widen what the server allows, but this page now behaves differently from the other project pages (TECH-1-6).
- Blocking: the "private PDF" zone accepts PNG, JPG and EML files and uses the picker's generic wording (TECH-1-1). The "I have checked this file" tick carries over to a newly uploaded file, so `checked: true` can be sent for a file the person never confirmed (TECH-1-2).
- Blocking (low): several acceptance-criterion tests are missing, including a 401 on the write, a 404 or 5xx on the options read, and the PDF kept after a 409 (TECH-1-3).
- LB-2 is flagged, not worked around (TECH-1-7). Both F-71 carry-overs are verified.
