UPLOAD · ONE FIELD FOR THE WHOLE PLATFORM · 4 CONCEPTS · 22 NOV 2026

How people add a file

The app has four different upload looks today, and only Setup uses the design system’s drop zone. Pick one concept and it becomes the single upload field everywhere: proof on work items and start forms, Assign PM, outcomes, client responses, Setup templates. Each concept is drawn in the same six states, in the Assign PM drawer and on a phone. Same rules for all: it uploads at once, says what it accepts, never guesses, and a closed record says why.

CONCEPT A

Drop zone, as the design system has it

The FileUpload already in the design system, used everywhere: a dashed box that says what it takes, files as rows under it with Remove, and a one-line “Add another file” zone once something is in.

Clearest for first-time users and drag and drop. The tallest of the four: about 100px empty, which is a lot in a drawer with several fields.

CONCEPT B

A field like every other input

Same 2px border and 48px height as the PM select and the Note box, with “Choose file” on the right. The chosen file fills the field; more files stack as more fields with an “Add another file” field last. Drop still works on the field.

Calmest in forms and lines up with the other fields. Drag and drop is less obvious, and many files take a lot of rows.

CONCEPT C

Attachment panel

A small bordered panel with “FILES · N” and “Add file” in its head. Empty, it explains itself; filled, it is a list with one row per file. The whole panel takes a drop.

Best where several files are normal (evidence, minutes with attachments) and the count matters. Heavier for a single optional file.

CONCEPT D

Slim strip and chips

One 48px dashed line to drop or choose, with the formats at the right, and the files as compact chips under it that wrap. Error shows on the chip and in words below.

Smallest footprint, so drawers stay short. Chips cut long file names sooner, and the meta (size, state) is shorter.
