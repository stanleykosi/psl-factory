# Component rationale

Every component on a screen earns its place: why it is needed, what it holds, where
it is used, what it beat, and which states it has. Screens list the components they
use (`components: CMP-n` in screens.md).

Screen IDs used below (planned; screens.md defines them when the screen set is drawn):
SCR-01 Work queue · SCR-02 Work item · SCR-03 Decision (phone) · SCR-04 Start work ·
SCR-05 Assistant · SCR-06 Factory floor · SCR-07 Project journey · SCR-08 Document review ·
SCR-09 Import and reconcile · SCR-10 Exceptions · SCR-11 Register · SCR-12 Report ·
SCR-13 Setup · SCR-14 Verified outputs · SCR-15 Notifications · SCR-16 Record a response ·
SCR-17 Sign in · SCR-18 Restricted payroll matching.

Concept: CON-C Assembly line (chosen 12 Nov 2026).

## Components

- CMP-01 | Top navigation bar | why: every user moves between queue, floor, projects, assistant and outputs from any screen on any device (S-03, S-10, C-01) | what: fixed destinations Queue, Floor, Projects, Assistant, Outputs, Setup (Setup only for Leads), Start work action, signed-in person and role | where: SCR-01, SCR-02, SCR-04, SCR-05, SCR-06, SCR-07, SCR-08, SCR-09, SCR-10, SCR-11, SCR-12, SCR-13, SCR-14, SCR-15, SCR-16, SCR-18, SCR-19, SCR-20, SCR-21, SCR-22, SCR-23, SCR-24, SCR-25, SCR-26, SCR-27, SCR-28, SCR-29, SCR-30, SCR-31, SCR-33, SCR-38, SCR-32, SCR-34, SCR-35, SCR-36, SCR-37 | instead of: a left sidebar (concept A/D; costs width on tablets and turns into a hidden menu on phones anyway), bottom tabs on desktop (wasted on large screens) | states: default, current page underlined in orange, collapsed to a menu button below 720px, menu open, focus
- CMP-02 | Station track | why: shows which station a piece of work is at and which are done, so people see where it is held (J-01, J-04, S-04, R-01) | what: the line's stations in order from the factory definition (4 to 11 per line), each with number, name, one-line status; current station in orange | where: SCR-02, SCR-07 | instead of: a vertical timeline (concept A/B; hides the shape of the line), a progress bar alone (loses the station names) | states: done, current needs a person, current processing by an agent or service, waiting, stopped, not started, scrolls sideways on phones
- CMP-03 | Mini station bar | why: lets a list row or phone screen show position on the line in a few pixels (J-01, J-02, C-06) | what: one segment per station, filled for done, orange for the current station when someone must act, blue when processing; text "Station 4 of 7 · Finance review" beside it | where: SCR-01, SCR-03, SCR-07, SCR-10 | instead of: a progress circle (concept D; reads as a percentage, not as stations), a text-only status (slower to scan) | states: in progress, needs action, processing, stopped, all done
- CMP-04 | Facts strip | why: keeps drafted, reviewed, approved, sent, receipt recorded and verified as six separate facts so nobody mistakes one for another; paid kept apart (R-01, R-02, G-02) | what: six boxes from the work item's records, each earned (dark), current (orange tint) or not yet (blank), plus a note that paid is tracked by Finance | where: SCR-02, SCR-14, SCR-20, SCR-30, SCR-36 | instead of: one status chip (merges facts, the error the rules forbid), a checklist (concept D; reads like a to-do list) | states: earned, current, not yet, unknown shown as "Unknown" never as empty or zero
- CMP-05 | State tag | why: names the work item's state in the factory's own words so the reason it is held is explicit (S-04, J-05, J-07) | what: always on one line (never wraps; the column grows to fit the longest state), one of Ready to continue, Processing, Waiting, Awaiting Finance decision, Owner needed, Setup needed, Action needed, Effect uncertain, Awaiting reconciliation, Verified, Cancellation requested, Cancelled, Stopped: invoice follow-up needed | where: SCR-01, SCR-02, SCR-03, SCR-07, SCR-10, SCR-14 | instead of: colour dots alone (fail for colour-blind users), icons alone (meaning not obvious) | states: one colour family per group (needs a person: orange; processing: blue; verified: green; waiting: amber; cancelled: grey), each with its text
- CMP-06 | Queue tabs | why: splits the queue into what needs me, decisions, exceptions, active, unassigned and verified, with counts (J-01, J-02, C-06) | what: each tab's count sits in a small square count badge (mono 11px; grey on unselected tabs, translucent white on the selected one), six fixed queues with counts from current records the user may see | where: SCR-01, SCR-24 | instead of: a dropdown (hides the counts that drive the day), separate pages (slower switching) | states: default, selected, focus, count zero shows "0" not hidden, wraps to two rows on phones
- CMP-07 | Work list | why: lets people scan many items and open one, with where it is and why it waits (J-01, C-06) | what: per row the work title, line and reference, mini station bar, state tag with who it waits for, age; up to 50 rows then "Show more" | where: SCR-01, SCR-11, SCR-14 | instead of: cards (concept B; fewer per screen), kanban columns (state changes come from decisions, not dragging) | states: default, hover, focus, loading rows, empty ("Nothing needs you right now"), error with retry, stacked rows on phones
- CMP-08 | Floor track | why: the signature overview of every line and where work sits on it (S-05, J-08) | what: one row per line with its stations as squares, filled where work is, orange where a person must act, a note per line; in the build, work moves as tokens with motion | where: SCR-01, SCR-06 | instead of: an illustration (concept B; can't show live counts precisely), chips only (concept D; loses the line shape) | states: live, updating, a station needing action, empty line, reduced motion (no movement, counts only), phone (lines stack vertically)
- CMP-09 | Agent work panel | why: shows what an agent read and drafted, in its own blue panel labelled as unable to approve, send or pay, so agent work never looks like a decision (R-03, S-10) | what: numbered steps with the record each one read and the time, and the result ("v2 drafted, marked DRAFTED") | where: SCR-02, SCR-05, SCR-18, SCR-20, SCR-25, SCR-26, SCR-28, SCR-30, SCR-31, SCR-33, SCR-32, SCR-36 | instead of: mixing agent lines into one activity feed (concept D; easier to confuse with people), hiding agent work (loses trust and evidence) | states: running with the current step, finished, stopped with a reason, no agent work on this item
- CMP-10 | Decision panel | why: lets the right role approve, return or reject one exact version, with what is being decided in plain view (J-02, R-04, R-01) | what: station name, who may decide and whether that is you, amount, basis, recipient, version and change, note field, Approve, Return, Reject, and what approving does not do | where: SCR-02, SCR-03, SCR-08 | instead of: a modal (hides the evidence behind it), inline buttons in the list (too easy to approve without reading) | states: you can decide, someone else must decide (read only, names the role), note required before return or reject, submitting, decided (shows who and when), stale version (asks to reload the new version)
- CMP-11 | Phone action bar | why: puts the decision actions within thumb reach with large targets (J-02, G-04, C-01, C-02) | what: Approve (full width), Return and Reject side by side, one line on what approving does | where: SCR-03 | instead of: actions at the top (hard to reach), a menu (extra tap) | states: default, pressed, submitting, done with next decision link, disabled with reason
- CMP-12 | Assistant thread | why: lets people ask in plain words and see the steps taken, the answer and its sources (S-10, J-10, J-11, R-08) | what: the user's message, the assistant's ticked steps, the answer, source tags, and any draft card; history per conversation | where: SCR-05 | instead of: a drawer on every page (design engineer chose a full page for a richer, more interactive experience), a form wizard (loses free questions) | states: empty with suggestions, thinking with live steps, streaming answer, answered, cannot answer (says why, e.g. no access), error with retry
- CMP-13 | Draft card | why: shows what the assistant created as a draft, never as a reviewed or sent document, and lets the person start the normal line (J-10, R-08, R-03) | what: draft title, the key fields (amount from contract terms, recipient, template), DRAFTED · NOT REVIEWED label, Start the line, Edit draft, the next station | where: SCR-05 | instead of: the assistant starting work by itself (would act without a person), a plain text reply (hard to check) | states: drafted, editing, started (shows the new reference and link), could not draft (missing record named)
- CMP-14 | Source tag | why: every answer and draft shows the records it came from, so people can check it (R-08, R-03) | what: record type and reference, linking to the record | where: SCR-02, SCR-03, SCR-05 | instead of: footnote numbers (one more step to understand) | states: default, hover, focus, record no longer visible to you (shown as restricted)
- CMP-15 | Context panel | why: shows the project the assistant is working in, the records it read and the person's access, so the scope of an answer is visible (R-08, R-04) | what: project, records read, your access on it, the limits of the assistant | where: SCR-05 | instead of: hiding the context (answers look like they come from nowhere) | states: no project yet, project set, records listed, collapsed on tablets and phones
- CMP-16 | Sample data label | why: anything sample, test or mock is visibly labelled (R-06) | what: "SAMPLE DATA" or "TEST TEMPLATE" in the content's place | where: SCR-01, SCR-02, SCR-03, SCR-04, SCR-05, SCR-08, SCR-09, SCR-14, SCR-16, SCR-18, SCR-19, SCR-20, SCR-21, SCR-22 | instead of: a banner once per session (easy to forget) | states: sample data, test template, mock delivery
- CMP-17 | Prompt suggestions | why: shows what the assistant can do without training (S-10, G-01) | what: three to five suggestions based on the person's role and current work | where: SCR-05 | instead of: a help page (rarely read) | states: default, hover, focus, hidden once a conversation has started on phones

- CMP-18 | Agent avatar | why: gives each department agent a face (Tola, Chidi, Zainab) so agent work is never mistaken for a person's decision (R-03, S-10) | what: the agent's avatar on its mascot tint, name and role; size 20, 32 or 40px | where: SCR-01, SCR-02, SCR-03, SCR-05, SCR-15, SCR-18, SCR-20, SCR-25, SCR-26, SCR-28, SCR-30, SCR-31, SCR-33, SCR-32, SCR-36 | instead of: a generic robot icon (no personality, and the same for every department), people's initials (confusable with people) | states: default, working (spinner ring in action blue), done, can't (no change to the avatar; the message explains)
- CMP-19 | Alert message | why: tells people on WhatsApp and email what is waiting for them, without exposing amounts or client details (S-06, J-02, J-09) | what: the agent avatar and name, one line on what is waiting, the work reference, a link into the app; daily digest variant | where: SCR-15 | instead of: rich messages with figures (privacy, and Meta template limits), in-app only (people miss it) | states: decision waiting, information requested, stuck, digest
- CMP-20 | Response record form | why: lets staff record a client's or team's response with proof, since they do not log in (J-03, S-07) | what: who responded (client role or team), what they did (approved, changes requested, signed, rejected), when, uploaded proof, a confirmation that it is genuine | where: SCR-16 | instead of: a free-text note (no structure for the factory to check), emailing proof to Finance (lost) | states: default, file uploading, validation (proof and date required), recorded
- CMP-21 | Sign-in form | why: people sign in once, including when they arrive from an alert on a phone (C-05, J-02) | what: email or username, password, a keep-me-signed-in choice, the page they were going to | where: SCR-17 | instead of: magic links only (depends on email access on the phone) | states: default, submitting, wrong details, locked out
- CMP-22 | List toolbar | why: every list needs the same way to find and narrow records, so people learn it once (design engineer's request; Linear and Attio filter pattern, REF-02, REF-12) | what: search box with icon, Filter button showing how many filters are on, result count, applied filters as removable chips with Clear all; the filter panel lists line, project, state and who it waits on; on a phone a search box and a 44px filter icon, with filters in a bottom sheet | where: SCR-01, SCR-10, SCR-11, SCR-14, SCR-15, SCR-20, SCR-21, SCR-22, SCR-26, SCR-29, SCR-34, SCR-35, SCR-37 | instead of: separate tabs per line (they multiply and hide combinations), a search-only box (cannot narrow by state) | states: default, typing, filters applied, filter panel open, no results
- CMP-23 | Start work split button and drawer | why: starting work is the most common action, and people should not leave My work to do it; most lines need two or three fields (design engineer's choice, concept 1; GitLab create flow, Carbon side panel) | what: sits in the top bar on every page (phone: "+ Start" in the top bar); "+ Start work" opens the most-used line; the arrow opens a menu of lines the person may start, all lines, and "Describe it to Tola"; the drawer holds the line's intake and a one-line "what happens next" | where: SCR-01, SCR-04, every page with the top bar, SCR-23 | instead of: a separate Start work page (loses the queue), a modal (blocks the queue) | states: menu open, choose a line, line chosen, needs fixing, starting
- CMP-24 | Callout | why: short messages above a form or on a work item must say how serious they are without a decorative side bar (design engineer's request) | what: tinted box with a leading icon that names the kind: warning triangle for problems and blocks (red or amber), info "i" for information (blue), tick for success (green); text in the matching dark colour, at least 4.5:1 contrast | where: SCR-02, SCR-03, SCR-04, SCR-09, SCR-13, SCR-16, SCR-17, SCR-20, SCR-21, SCR-23, SCR-24, SCR-25, SCR-26, SCR-27, SCR-28, SCR-33, SCR-32, SCR-34, SCR-35, SCR-37 | instead of: a 4px left border (looks like a selection marker and carries no meaning for screen readers) | states: warning, info, success
